# ADR-0072：目标由 todo 清单 + 证据验收驱动跨回合续跑

**状态**：accepted
**日期**：2026-09-22
**相关**：ADR-0024（长程 todo 闭环 —— 本 ADR 建立在它之上）、
ADR-0010（Agent 无状态）、ADR-0014（不建 hook 系统）、
ADR-0027（完工检查与轮预算 —— 其决策 2 已被 ADR-0041 撤回）、
ADR-0041（撤掉完工复核回合）、ADR-0047（不做跨回合输入队列）、
ADR-0065（子 agent 跨回合投递）、ADR-0009/0011/0013（信道契约）

## 背景

ADR-0041 撤掉了「完工复核回合」：执行回合的模型自述「已完成」不可信，代价还不止一轮。
该 ADR 的 Consequences 留下一条硬要求：

> 若日后实测「自称完工但并未完工」的比例不可忽略，应重新引入**某个**机制 ——
> 但届时应先解决本案暴露的真问题：**它不该只在一条入口上生效**。

ADR-0024 已经设计了长程 todo 闭环（清单落盘、回合边界注入、`has_open_items()` 推进判据），
但它在决策 4 里诚实记下了一个天花板：

> **todo 是模型的「自陈」，不是「验收」**。本 ADR 只能强制「再问一次」，不能强制「真的做完」——
> 模型可以把全部项标成 `completed` 然后收工，代码照约删除。
> **真正的保证来自可验证的验收**（测试绿、构建过），不来自清单。

本 ADR 补上那一层**验收**，并同时满足 ADR-0041 的两条硬要求。

一期的跨回合追问（`apps/coding-agent/src/post_turn.rs`）与二期的定时 tick
（`apps/coding-agent/src/app_loop.rs` 的 `should_tick`）都只回答「**该不该醒**」。
ADR-0024 回答了「**还剩什么**」。两者都不回答「**声称做完的那条，真做完了吗**」。

## 决策

### D1：目标由用户一句话给出；「什么算完成」由 agent 的 todo 清单承载

新增 `/goal <目标>` 与 `--goal <目标>`。用户**只写目标**，不写验收条件。

**不让用户写条件**的理由：用户不知道仓里有哪些测试、该验哪条 ——
要他写「什么算完成」等于把实现细节推回给用户，而他往往写不出来。

**不让 agent 事前冻结契约**（本 ADR 早期版本的设计）：真实干活时计划会演化
（干到第 3 步才发现还要改文档）。冻结契约不允许追加 ⇒ 逼 agent 第一轮就想全，与实际不符。
TODO 清单允许追加，但**不允许静默删除**（见 D3）。

⇒ 分工是：**清单提供「查什么」，判官提供「查到什么」**。

### D2：清单层直接实现 ADR-0024，不重新设计

`adapters/tools-todo` 新 crate、`TodoStore` 唯一真值、`apply` 全量重写、`render_block` 字节稳定、
`has_open_items()` 推进判据、`MAX_FOLLOW_UPS = 8`、子 registry 无 `todo` —— 全部照 ADR-0024。

**本 ADR 明确采纳落盘**：真值在 `<sessions_dir>/<stem>.todo.json`，与会话同级。

| 理由 | 说明 |
|---|---|
| 活过压缩 | 压缩摘的就是旧消息；todo 在 session 里必然被摘掉（ADR-0021 已记过该缺口） |
| 活过重启 | 复用 `Wiring::latest_session_path()` 既有恢复路径，**零新机制** |
| 活过回合 | 长程任务必然撞 `max_rounds` ⇒ 多回合；真值不能只在回合内有效 |
| `/new` 语义清楚 | 换 stem ⇒ 计划天然归零 |
| 零新目录 | 会话同级 ⇒ `YUSHAN_SESSIONS_DIR` 的测试覆盖自动生效 |

`-p` / `--json` ⇒ **纯内存 store，不落盘**（一次性会话没有「下次」）。

**与目标状态的区别**：目标是「本回合想达到什么」（不落盘，`--resume` 不恢复，见 D10）；
清单是「还剩什么活」（落盘，重启后仍有效）。前者过期即失效，后者不会。

### D3：清单的两条硬规则由代码执行，不靠模型自觉

都在 `TodoStore::apply` 里：

| 规则 | 防什么 |
|---|---|
| **拒绝丢弃既有非终态项** | 模型发一个 `[]` 就关掉整个闭环 |
| **无 open 项 ⇒ 清空 + 删文件** | 判据写「全部 Completed」时，一个被放弃的项会永久卡住 |

配套终止态 `Cancelled`：它是模型能**诚实停下**的唯一出口。
没有它，模型想让环停下就得把没做完的事标成 `completed` —— 那是**伪造完成**。

### D4：判官读清单 + 证据，**不读助手自述**

判官的输入分三段：

| 段 | 内容 | 可否支撑「工作已完成」 |
|---|---|---|
| 清单 | todo 全部项（内容 + 状态），含 `skipped` 与理由 | 这是**待核对的问题**，不是证据 |
| 证据 | 工具调用（名字 + 参数）、工具输出、harness 事实（HEAD 变化 / 轮数 / 耗时 / 工具调用数） | 可以 |
| 助手自述 | 助手本轮正文 | **不可以** |

两段可按 `ContentBlock` 变体精确区分（工具结果是 `ContentBlock::ToolResult`，
助手正文是 `ContentBlock::Text`）—— **不靠 `Role` 区分**，因为工具结果以 `Role::User` 进 session。

**判官的任务不是「条件满足了吗」，而是「逐条核对」**：

```
对清单里每个非终态项，在证据里找它的完成凭据：
  - 找得到 ⇒ 该项 OK
  - 找不到 ⇒ 该项未完成 ⇒ 整体 NOT_MET
```

⇒ 判官输出必须**逐条**回答，不允许一句「都做完了」结论式放行。

**为什么清单进证据窗口但状态不算证据**：模型把某项标成 `completed` 是**自陈**（ADR-0024 天花板），
不能当证据；但它标了哪些项、跳过了哪些项，是判官**必须核对的对象**。

### D5：`MET` 的充分条件是机制强制的，不靠判官自觉

判官输出：

```
VERDICT: MET | NOT_MET | BLOCKED
ITEMS:
- <清单项原文或编号> | OK | <证据里逐字摘录的一段，≥12 字符>
- <清单项原文或编号> | MISSING | -
EVIDENCE: "<从证据段逐字摘录的一段，≥12 字符>"
```

`MET` 成立的**三个条件缺一不可**：

1. `VERDICT: MET`；
2. `ITEMS` 里**每个非终态项**都标了 `OK`，且每项的引用都能在证据窗口里逐字命中；
3. 至少一条引用命中。

任一不满足 ⇒ 降级 `NOT_MET`。

**「MET 必须逐字命中证据窗口」是本设计的核心防幻觉机制。**
harness 在排除助手自述的证据窗口内做归一化空白后的子串匹配。

⇒ **模型把项标成 `completed` 但没跑出凭据，判官结构上不可能放行。**
这是 ADR-0041 所暴露真问题的正面解法，且是机制保证而非提示词叮嘱。

**三家里没有一家这么做**：codex 靠 `templates/goals/continuation.md` 的提示词叮嘱模型自审；
CodeWhale 靠模型**自填** `verification { status, check, summary }` 回执且 harness 不校验。
引用校验是本 ADR 唯一强于既有实现的地方。

### D6：只读最后一轮 ⇒ 判官输入 O(1)

判官读**本轮内已进入模型上下文**的内容，不读整段 session，也不做滚动摘要。

- 收益：判官输入与总轮数无关，成本不随轮数线性增长。
- 代价：跨轮证据不可见 ⇒ 判官只能核对**本轮可验的项**。跨轮才完成的项拿不出凭据 ⇒
  被保守地判为未完成。缓解：guideline 要求 agent 在收尾轮**重跑关键验证**（测试/构建）。
- 否决读整段 session / 滚动摘要：成本线性增长，且把模型自己的叙述重新喂给判官，
  放大 ADR-0041 的坑。

清单 + 证据摘录合计 ≤ 6000 B。清单过长（>600 token）⇒ 提示 agent 合并条目，**不静默截断**
（截了判官就看不见被截的项）。

### D7：判官是一次独立的模型调用，不经 Agent、不带工具表、关闭思考

参照 `crates/ys-loop/src/summarize.rs` 的 `ModelSummarizer` 模式（「用模型读一段内容做加工」）：
判官调用 `model.complete`，请求形态为
`ModelRequest { messages, tools: Arc::new(vec![]), system, max_tokens: 128, temperature: None, boundary: None, thinking: Some(ThinkingOverride::off()) }`。

继承该模式注释里的两条硬理由：

1. **不带工具表** —— 省 token，且杜绝判官吐 `tool_call`（它拿不到工具结果）。
2. **关闭思考** —— 思考计入 `max_tokens`，能把预算吃光导致正文为 0 词。
   判官 `max_tokens = 128` 比摘要的 1024 更紧 ⇒ 关闭思考是**必需**而非可选。

判官**不扩 `ys-event`、不加 `AgentEvent` 变体**：目标属 coding-agent，
进核心词汇会让所有消费者都得认识目标概念。

### D8：判官自由文本永不回灌进 session

判官结果只以**一行标签**进 session（`Role::Harness`）：

```
[harness] 目标判定：not_met（继续）
[harness] 目标判定：met（停止）
[harness] 目标判定：blocked（停止）：<理由 ≤120 字>
```

理由只给人看（stderr / 终态摘要），不进模型上下文。两个理由：
① 断掉「恶意文本 → 判官 → 回灌 → 再进模型上下文」的注入放大回路；
② 每轮理由进 session = 每轮永久 token 成本，且随上下文复利。

### D9：假阳性远比假阴性严重 ⇒ 全部降级偏保守

| 情况 | 处理 |
|---|---|
| 解析失败 / 空输出 | `NOT_MET`，计入可靠性计数；**不重试解析** |
| `MET` 但任一项引用未命中证据 | 降级 `NOT_MET`，计入可靠性计数 |
| `NOT_MET` | 继续 |
| `BLOCKED` | 停止（条件不可达成 ⇒ 让人能及时止损） |
| 模型调用失败 / 超时 | 重试**一次** → 仍失败则**停止** |

「模型调用失败后停止」而非「继续」：没有判据就没有停止条件 ⇒ 跑飞。
「解析失败不重试」：同一输出重试无益，只会多烧一次调用。

解析宽容但严格：扫前 8 行非空行取 `VERDICT`，值**必须整词等于** `MET|NOT_MET|BLOCKED`
（不做前缀匹配 —— 否则 `METRICALLY` 会被误判成 MET，正是最危险的假阳性方向）。

### D10：闸门分硬软两类；轮数只做软提醒，不设 token 预算

闸门全部由 app 层 `GoalState` 计数。

| 闸门 | 形态 | 默认 | 触发结果 |
|---|---|---|---|
| 轮数 | **软提醒** | 60 轮（触发后翻倍） | 提示，**不中断** |
| 墙钟 | 硬闸门 | 48 h | 未达成（预算） |
| 无进展 stall | 硬闸门 | 连续 3 轮 todo 集合不变 **且** 模型自称收尾 | 无进展 |
| 判官可靠性 | 硬闸门 | 连续 2 次解析失败 / 引用未命中 | 判官不可靠 |
| 回合健康 | 硬闸门 | 主回合 `Failed`/`Cancelled`/`MaxRounds`/`Truncated`/`NoOutput` | 回合失败（立即停） |
| token 预算 | **不设** | — | — |

**轮数只做软提醒，不做硬顶。** 依据 ADR-0027 决策 6（「真正的兜底是这条**小时级**阀门，不是轮数」）
与仓库既有形态：`Config::max_rounds` 的 app 默认是 `u32::MAX`（`apps/coding-agent/src/config.rs:434`）、
`Config::max_turn_duration` 默认 48 h（`config.rs:441`）、回合内轮数软提醒默认 60 轮且触发后翻倍
（`crates/ys-component/src/limits.rs:34`）。不引入比仓库现状更紧的硬顶。

**token 预算不设。** 去掉后「长任务被 token 掐死」的风险改由墙钟（48 h）兜底；
代价是极端情况下的花费无上界，由用户自担。

**stall = 「剩余 todo 集合连续多轮不变」**。判官只答「核对通过没有」，不答「你有没有在原地打转」；
后者用**清单本身**判定：

```
stall_digest = DefaultHasher( Σ(归一化内容 ‖ 状态) for 非终态项 )
```

归一化链：折叠空白 → 小写 → 排序 → 去重 → 喂 `DefaultHasher`。

| 为什么用清单而非命令输出 | 说明 |
|---|---|
| 天然免疫「输出微变」 | 反复跑同一条测试命令时输出带不同耗时 ⇒ 哈希输出会漏检；清单是离散集合，不受日志噪声影响 |
| 与推进判据同源 | 判据是 `has_open_items()`，停滞就是「这些项一字未变」 |
| 零额外采集成本 | 不需要从 session 抽工具调用、不需要归一化参数/输出 |
| 不读助手自述 | 清单是结构化数据，不可能被模型换个措辞绕过 |

- **只算非终态项**：已完成的项不参与（否则模型把已完成项重新描述一遍就重置了 stall）。
- **和「模型自称收尾」取 AND**（ADR-0024 决策 d）：只靠集合不变会误杀
  「一轮里干了活但还没更新状态」的情形。
- 阈值取 3 轮而非 2 轮：修 bug 常见的「改 → 测 → 再改 → 再测」需要至少两轮往返，
  2 轮会把**正常的多轮迭代**误判成卡死。

**用 `DefaultHasher` 而不是 `sha256`**：只比相邻两轮（O(1)、不落盘、不跨进程）
⇒ 不需要密码学强度。实测（单轮 21 KB 证据）`sha256` 36.3 µs / `DefaultHasher` 3.4 µs（快 10 倍）；
且 `sha256` 会新增 9 个依赖包，而 workspace 的 `Cargo.lock` 里目前没有 `sha2`。
`DefaultHasher` 跨 Rust 版本不稳定，但本机制**不需要**这个保证。

stall 与判官结论正交：判官说「还没达到」（事实），stall 说「也没进展」（趋势）。
清单变了但判官仍说 `NOT_MET` ⇒ 有进展，stall 归零；清单完全没变 ⇒ 才累加。

闸门可配置（`config.json` 的 `goal` 段），默认值宽松；`0` = 关闭（沿用仓库惯例）。

### D11：两条入口都必须生效

ADR-0041 的硬要求。本期实现的落点：

| 入口 | 落点 |
|---|---|
| TUI | `app_loop.rs` 的 `Request::Prompt` 臂内，回合结束后求值；未满足则追加一轮 |
| `-p` / `--json` | `run_single_turn` 外的循环 |

求值函数**只有一份**（`goal::evaluate` / `goal::after_turn`），两条入口都调它。

**继续条件**：`todo.has_open_items() ∨ (goal.is_some() ∧ ¬goal.met) ∨ should_follow_up(head)`。
⇒ `-p` 的**默认行为不变**（不写清单、不传 `--goal` ⇒ 跑完即退出），但**不是「逐字节不变」**
—— 加 `todo` 工具本身会改工具表（预期的前缀漂移，全入口同步）。
退出码：`0` = 达成（或未指定目标且清单已空）；`2` = 未达成（预算 / 无进展 / 阻塞 / 判官不可用）。

### D12：目标期间抑制一期/二期的自驱

目标激活期间，一期的 HEAD 自动追问与二期的 tick 唤醒**都不再自行追加回合**（否则轮数翻倍）。
目标期间续跑**只**由目标判据驱动。

### D13：判据接口是枚举 + 单个 `async fn evaluate`，不建 trait

同一时刻只有一个活动目标，无多态需求 ⇒ 不建 trait（trait 会退化成投机泛化）。
判据类型（`GoalSpec` / `Verdict` / `ItemVerdict`）放 `crates/ys-protocol`（纯数据、无 tokio），
判官实现放 app 层（`apps/coding-agent/src/goal.rs` + `goal_judge.rs`）。

### D14：目标不落盘，`--resume` 不恢复

目标状态不落盘 ⇒ `--resume` 不恢复目标。重置预算等于重开跑飞口子。
`--resume` 后目标未激活。

⚠️ **todo 清单是另一回事 —— 它落盘**（D2）。目标是「本回合想达到什么」，
清单是「还剩什么活」。前者过期即失效，后者重启后仍然有效。

## 后果

**正面**

- ADR-0024 自陈的天花板被补上：todo 从「自陈」升级为「可核对」。
- ADR-0041 暴露的两个真问题都被处理：判据外部可读（机制保证）、两条入口都生效。
- 「模型自称完成」在机制上无法通关（引用必须逐字命中证据窗口）。
- 判官输入 O(1)，成本不随轮数线性增长。
- stall 判据与推进判据同源，且天然免疫日志噪声。
- 判官不调工具、不扩权、不产生给模型的指令 ⇒ 注入面收窄到「判错」。

**负面**

- 多一次模型调用 / 轮（判官开销不计入任何预算，因为 token 预算不设）。
- 跨轮证据不可见 ⇒ 跨轮完成的项可能被保守判为未完成（靠收尾轮重跑验证缓解）。
- **token 预算不设 ⇒ 极端情况下花费无上界**（由墙钟 48 h 兜底）。
- 两个切片的实现成本（todo crate ~420 行 + 120 测试，验收层另计）。

**中性 / 待办**

- 判官用主模型还是更便宜的模型，未定（仓库当前无独立小模型配置）。
- ADR-0024 设计的 `ToolPlugin` 装配缝尚未实现（`grep ToolPlugin` = 0）；
  `todo` 先按 `tools-basic` / `tools-web` 同形落到 adapter crate，装配缝落地后再对齐。

**明确不做**

通用 hook 系统；多目标 / 目标树；跨会话目标恢复；默认开启的完工复核；
判官调工具；助手自述进证据池；扩 `ys-event` 词汇；把判官放进 `ys-runtime` 公共 API；
子 agent 的 todo（同时打破字节前缀与单写者不变量，理由见 `docs/arch/long-horizon-todo/design.md` §7.4 e）。

完整设计与测试矩阵见 `docs/arch/cross-turn-advance/design.md` §5。
