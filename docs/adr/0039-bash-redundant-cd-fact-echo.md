# 0039 — 冗余 `cd` 的**条件式事实回显**：工具给旁证，不剥离、不拒绝、不常驻

`bash` 每次调用都在 workspace 根起新 shell（`adapters/tools-basic/src/bash.rs` 的
`current_dir(&self.workspace)`），模型却仍在命令前加 `cd <workspace> && `（31 字符，恒为同一路径，
对行为零影响）。该前缀的成因**不是「没告诉它」** —— 系统提示开头就有 `Current working directory: …`
并说全了「相对路径按它解析、每次调用是新 shell」。缺的是**旁证**：模型拿不到任何「你在哪」的回执，
自证 31 字符且从不失败，求证要一整个来回 ⇒ 每次重新钉一次是**理性选择**。

本 ADR 记的是：为什么工具侧只做「在冗余发生时补一行可核对的事实」，以及**为什么这条改动预先
登记了「无效就删」的判据**。

## Status

accepted（2026-10-14）

## 背景

**措辞这条通道已被证明不可靠。** `docs/arch/bash-cwd-contract/context.md` 记的变体实验里，
「cwd 段置顶 + 说完整」把 `cd→根` 从 100% 压到 **0%**（变体 `e`，n=1，56 次调用）。但该修复
（`d49c66a` 置顶说全、`34b79ba` 清掉描述里的禁令与逃生口）落地后的一次真实会话
（`1791990139`，跑在**含全部修复**的二进制上：`target/debug/ys-coding-agent` 构建于 23:00，
`prompt.rs` 为 08:34 版、`bash.rs` 为 22:58 版）测得 **60/62 ≈ 97%**。两个 n=1 方向相反
⇒ 措辞通道的效应不稳定，不该继续当主力。

**真实会话的形态**（`python3 scripts/bash-cd-rate.py --workspace …`）：

| 会话 | 模型 | bash 调用 | 以 `cd ` 开头 | 其中 `cd <根> &&` | 首次出现在第几次调用 |
|---|---|---:|---:|---:|---:|
| `1791818019` / `1791819446` | MiniMax-M3 | 22 / 22 | 0 / 0 | 0 / 0 | — |
| `1791821478` | deepseek-flash | 4 | 1 | 1 | 4 |
| `1791906130` | 未记录 | 34 | 34 | 34 | 1 |
| `1791990139`（修复后） | deepseek-flash | 62 | 60 | 60 | **3** |

两条读出：① 首次带前缀出现在**第 3 次**调用（前两次用绝对路径），此后一次不落
⇒ 它是「**开局钉一次位置、然后复用模板**」，不是对某条命令不确定；② 「`cd <根> &&`」计数与
「以 `cd ` 开头」计数**完全相等**（五次会话无例外）⇒ 没有一条是「cd 去别处」，
**冗余与否可以在工具内静态判定**。

## 决策

**1. 只在判定为冗余的那一次，在结果末尾追一行纯事实**（`adapters/tools-basic/src/bash.rs`）
—— `[bash: this shell already started in <ws>; the leading cd changed nothing]`。

- **命令照原样执行**：不剥离、不拒绝、不改写模型输入。
- **条件式**：好行为的那次不带任何附言，故成本**自我消灭**。
- **落在末尾**：截断通知（`[Truncated N lines.]`，前插）必须紧贴它说明的正文；且保住既有的
  「失败结果的最后一行是退码行」不变量。
- **`is_error` 不受影响**：它是事实，不是错误 —— 否则模型会道歉 + 重规划，代价是**一整轮调用**，
  远超它要省下的那几个字符。
- 判定只认**开头首段**的 `cd <path> && 余下`（`<path>` 允许裸串 / 单引号 / 双引号，两侧
  `canonicalize` 后比较），中段的 `cd` 不判 —— 病灶是「开局钉模板」，中段 `cd` 是真实位移。

**2. 工作目录不成立时硬报错**：`spawn` 前校验，区分「不存在」（`Working directory does not exist: …`，
对齐 pi）与「不是目录」。原先只报 `Failed to spawn command`，与「命令本身有问题」无法区分。

**3. 预先登记「无效就删」** —— 这是本决策的一部分，不是补充说明：

- 成本算术：注记约 20 est token/次，被瞄准的前缀约 9 est token/次。**有效** ⇒ 总计约 29 token
  （首次），此后归零；**完全无效** ⇒ 每次 29 token，**比不做更差**。故它是个「无效即净亏」的赌注。
- 判据（落地前写死，用 `scripts/bash-cd-rate.py` 采，同模型同任务型，≥3 个会话）：
  - `after_note == 0` 且 cd 占比显著低于基线 ⇒ 保留；
  - **`after_note > 0`（模型在拿到事实之后照旧加前缀）⇒ 删掉本回显** —— 通道无效，不再猜；
  - 回合数（会话 meta 的 `turns`）相对基线上升 ⇒ 删掉（说明注记触发了重规划）。

## 方案对比

| 方案 | 优点 | 代价 / 为何不取 |
|---|---|---|
| **A 条件式事实回显（采纳）** | 不依赖模型配合即可送达事实；成本随行为改善**归零**；不碰执行语义 | 若模型无视它则净亏（已登记删除判据）；注记里出现 `cd` 一词有 priming 风险（由判据 3 兜住）|
| B 每次调用都回显 cwd | 恒有旁证 | **常驻税**：实测路径下单会话约 888 token，而它要消灭的前缀总共才约 280 token ⇒ **净增约 3 倍** |
| C 静默剥离冗余前缀 | 零 token、模型无关 | **静默改写模型输入**；且它**不减少模型自己的输出**（前缀仍被生成）⇒ 治不了本质，只治执行侧 |
| D 给 bash 加 `cwd` 参数 | 「在子目录跑」有声明式表达 | **与病灶不相关**：模型加前缀是为了用相对路径，不是为了换目录；另带 schema 常驻 token，且引入 workspace 外执行的能力面（沙箱边界未定义）|
| E 继续改提示词 / 描述措辞 | 零代码 | 已被反例推翻（见背景）：效应不稳定，且每次验证要花额度、n=1 |

## Consequences

- **正面**：模型第一次拿到可核对的旁证，「我在哪」从赌注变成送达的事实；工作目录错误从
  「含糊的 spawn 失败」变成可操作的硬报错。
- **负面 / 如实记账**：**效果零数据**。这条改动能否改变行为，本轮**没有**对照结果 ——
  它的合法性完全建立在「无效就删」上（决策 3）。
- **边界（写进注释，不做）**：超时 / 中止两条路径返回 `ToolError`，不带注记；
  `ys-loop` 的回合级工具输出闸门（默认关闭）做**头部**截断，不会吃掉末尾的注记。
- **不受影响**：无冗余 `cd` 的调用结果逐字节不变（含既有 `[Truncated N lines.]` 文案）。
