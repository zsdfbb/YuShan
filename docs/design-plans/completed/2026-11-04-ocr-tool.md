# OCR 工具设计计划

> 对应架构设计：`docs/arch/ocr-tool/design.md`（v2，2026-11-04）
> 日期：2026-11-04
> 目标：新增 `ocr` 工具，把图片里的文字**连同位置信息**取成文本交给模型，作为当前仓库唯一的图片输入通道。

## 需求范围

### 范围内

（摘自 `docs/arch/ocr-tool/context.md` §需求范围，未扩展。）

- 图片格式：`png` / `jpg` / `jpeg` / `webp` / `gif` / `bmp` / `tiff`。
- **默认行级坐标**（完整形状与 golden fixture 见 design.md §1）。
- `word_boxes=true` ⇒ 词级（tesseract 用 `level 5`，Vision 退化为行框按空格切词），**强制落盘**。
- 语言经 `lang` 参数（默认 `chi_sim+eng`；拼装时校验字符集防注入），**仅 tesseract 生效**
  —— 故 Vision 下头行打 `lang=n/a` 且不入缓存键（design §2.3）。
- macOS 走 Vision（中文更好）；Vision 运行期失败则降级 tesseract，**必带 notice 不静默**。
- 超 8 KiB 自动落盘，结果给路径 + 行数 + 前 N 行（落盘**必是全量**，design §4.3）。
- 后端缺失时给出两平台安装命令。

### 范围外（明确不做的）

- **多模态**：把图片字节送进模型（需改 JSONL 契约 + 五层，非本需求）。
- **扫描 PDF**：留给 `pdf-analysis` skill（需页范围 / DPI 参数）。
- **图片显示**：TUI 渲染图片。
- **RapidOCR**：Debian/Ubuntu 从未打包，且其 CLI 不吐文本与坐标。
- **版面还原**（表格结构、阅读顺序重排）：`level 3` 段落信息不足以可靠还原表格，做一半比不做更误导。
- **改 `read` 的二进制错误文案**：另一件事。
- **`--psm` / `--oem` / `dpi` 暴露**：参数是「意图」，不是「引擎旋钮」（design §1）。
- **OSD**（方向/脚本检测）：失败率 3/8，开销 +43%~87%，混排页原理上无解（design §2.4）。

## 接口契约

> **本节与 design §1 冲突时，以 design §1 为准。** design §1 是输出格式的唯一定义。
> 本节只做摘录，不得在此处引入新写法。

输入 schema **只有 3 个字段**：

```json
{
  "path": "string (必填)",
  "lang": "string (默认 chi_sim+eng；Vision 后端下被忽略)",
  "word_boxes": "boolean (默认 false，强制落盘；Vision 后端退化为行框)"
}
```

### 三种输出形态

**头行**（三种粒度恒有，`#` 开头避免与坐标行混淆）：

```text
# <basename> <W>x<H> via=<tesseract|vision> lang=<生效值> lines=<N> filtered=<M>[ degraded=<原因>]
```

- `via=` 是**实际成功**的后端；`lang=` 是**实际生效**的语种参数。
- Vision 后端下 `lang=n/a`（该后端不消费 `lang`）。
- `lines=` 保留行数，`filtered=` 被 `width<6` / 纯空白滤掉的行数（空结果判定靠它）。
- `degraded=` 只在发生降级时出现，原因三选一：`vision-failed` / `lang-missing` / `word-boxes-unsupported`。

**行级**（默认，`word_boxes=false`）：

```text
<line_no> (<x>,<y>,<w>,<h>) conf_min:<conf> <text>
```

- `line_no` 是**本结果序号**（从 1 递增），不是 tesseract 的 `line_num`。
- 坐标为**原图像素**，左上原点；`w,h` 恒保留。
- `conf_min` 是该行 `level 5` 词的**最小**置信度，整数 0–100。**恒出现**，不过滤、不省略。

**词级**（`word_boxes=true`）：

```text
<line_no>.<word_no> (<x>,<y>,<w>,<h>) conf:<conf> <text>
```

**内联与落盘的格式完全相同** —— 落盘只是换了投递方式，不换格式。

### 两段 golden fixture（测试基线，改动即红）

```text
# shot.png 1200x900 via=tesseract lang=chi_sim+eng lines=2 filtered=0
1 (62,49,890,28) conf_min:96 第三章 配置文件说明
2 (61,116,906,26) conf_min:91 应用程序启动时会依次读取以下三个位置的配置文件，
```

```text
# shot.png 1200x900 via=vision lang=n/a lines=1 filtered=0 degraded=word-boxes-unsupported
1.1 (62,49,890,28) conf:0 第三章
```

Vision 无词级输出 ⇒ `word_boxes=true` 退化为**行框按空格切词**，`conf:0` 表示「该后端不提供置信度」；
`degraded=` 让退化可见，模型据此知道不能按置信度过滤。

## 关键约束

逐条硬约束，任一被违反即属设计偏离：

1. **零新增 Rust 依赖**。引擎一律 spawn 外部进程；不引入 image / OCR / base64 类 crate。
2. **`ys-core` 与 `ys-tool` 一行不改**。只用既有公开面：`Tool` trait、`truncate::{head, MAX_BYTES,
   MAX_LINES, SOFT_RESULT_BYTES}`、`append_notices`。
3. **不实现 `Tool::timeout()`**。与 `grep` / `find` / `ls` 同口径：外层回落 `RunLimits::bash_timeout`
   （默认 300s），内层用 `search::DEADLINE`（60s）⇒ 内层严格更早。理由：外层到点是 drop 工具 future，
   只有 `kill_on_drop` 生效（只杀直接子进程）⇒ 内外层相等会让 `swiftc` 的孙进程漏网成孤儿（design §3.1）。
   若将来实现，必须从 `ctx.tool_budget` 推导（照 `bash.rs:effective_deadline` 形态）。
4. **`lang` 在 Vision 下忽略且不入缓存键**。三处必须一致：schema 描述写明「Vision 下被忽略」、
   头行打 `lang=n/a`（不回显入参）、哈希不含 lang（否则同图按 lang 落多份内容相同的文件）（design §2.3）。
5. **落盘必是全量**。先写文件再截断回显；顺序写反就成半个文件。`word_boxes=true` **恒落盘**（design §4.3）。
6. **绝不按 `conf` 过滤**。只丢纯空白 + `width < 6` px 的行；实测 `conf: 0` 的行是真文本（design §4.2）。
7. **不启动期探测语言包**。`--list-langs` 要 1161 ms；语言包缺失按调用扫 stderr（`rc=0` 时的
   `Failed loading language`）惰性发现，**不缓存到进程状态**（design §7 注）。
8. 附带口径：`is_concurrency_safe = true`（只读输入 + 内容哈希幂等落盘 + 原子写）；
   不建 `YUSHAN_OCR_DIR`（落盘目录走构造器注入）；不改 `tools-web` 的 `backends.rs` 判据回写（跨需求，另立项）。

## 模块划分

（照 design.md「模块划分」表。4 个新文件 + 1 处可见性提升。）

| 模块 | 职责 | 核心抽象 |
|---|---|---|
| `adapters/tools-basic/src/ocr/mod.rs` | spec、参数校验、流水线编排、notice 拼装、可观测性字段。**不含后端细节** | `OcrTool` |
| `adapters/tools-basic/src/ocr/tsv.rs` | TSV → `Vec<OcrLine>` → 渲染。**纯函数、零 IO、零 tokio** | `parse_tsv`、`render`、`OcrLine` |
| `adapters/tools-basic/src/ocr/engine.rs` | 后端探测（注入式）、argv 构造、候选链、落盘 | `OcrEngine`、`Kind`、`spill` |
| `adapters/tools-basic/src/ocr/vision.swift` | Vision 调用 → 归一化坐标 → 输出 TSV | — |

依赖方向（design.md 模块图）：`mod.rs` → `tsv.rs` / `engine.rs` → `exec.rs`；`engine.rs` →
`vision.swift`（`include_str!` 内嵌）；`mod.rs` → `ys-tool::truncate` / `test_support::fake_bin`。

`exec.rs::find_in_path`（`:113`，现为私有）**提为 `pub(crate)`**，由 `engine.rs` 直接用 ——
路径探测只能有一个实现，复制一份就是第二个可能漂移的真值（与 `SearchBackends` 提取同理，`exec.rs:52-60`）。

## 风险与待验证

（照 design.md「已知风险与待验证项」。）

- [x] **语种默认值** —— 7 图 CER 实测钉死 `chi_sim+eng`。
- [x] **`psm` 选择** —— `psm 6` 固定；`psm 7` 多行图静默吐空（CER 100%），已证伪。
- [x] **`lang` 在 Vision 下的语义** —— 忽略 + 头行 `n/a` + 不入哈希（§2.3）。
- [x] **内外层超时关系** —— 不实现 `timeout()`，沿用 60s/300s（§3.1）。
- [x] **空结果三分** —— `lines=` / `filtered=` / stderr 三判据（§3.2）。
- [ ] **`swiftc` 缓存无 CI 覆盖** —— 靠纯函数测 + golden fixture + `#[ignore]` e2e。
- [ ] **缺语言包静默降级**（`rc=0`）—— 成功分支必须扫 stderr，只判退出码会漏。
- [ ] **40 MP 像素上限**是估计值，未实测解码峰值；首个真实超大图反馈时校准。
- [ ] **工具表指纹重算** —— 装配面 8 项，改一处必须改齐。
