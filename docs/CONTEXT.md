# YuShan — 通用语言

YuShan 是一个用于组装 Agent 的轻量 Rust Runtime。本文件定义讨论与代码中使用的领域词汇，只收录本项目特有语义的术语。

## 语言

### 回合、轮、追问与任务

本节定义四个**不同层级**的概念。前三个嵌套而非同义：**回合 ⊃ 轮**，追问是**相邻的两个回合**；
任务则是把多个回合括起来的**生命周期**。讨论与文档必须写明是哪一层。

**轮（Round）**：
**一次模型调用**（含它发起的工具执行）。这是最小计数单位：`BasicLoop` 每调一次模型就
`rounds += 1`（`crates/ys-loop/src/basic.rs:673`）。一个回合由一或多轮组成，受最大轮数约束。
_避免_：回合、步骤、迭代

**回合（Turn）**：
一次「输入进入 Runtime 到产出结果」的**完整处理**，即一次 `run_turn_chain`
（`apps/coding-agent/src/app_loop.rs:1687`）：模型与工具往复推进，直到给出回答、触顶或被取消。
一个回合包含一或多轮。
_避免_：Run（易与运行实例混淆）、循环迭代、会话

**追问（Follow-up）**：
由**系统**（非用户）在上一回合结束后自动追加的**下一个回合**。
⇒ 它是**回合**，不是轮，也不是独立的第三层；`AdvanceState::used` 记的是已追加的追问回合数
（`apps/coding-agent/src/turn_advance.rs:32`）。
⇒ 层级恒为「回合 ⊃ 轮」；追问与被追问之间是「回合 → 回合」的**相邻**关系，不是包含关系。
与插话（Steer）相对：Steer 不增回合数，追问**增**回合数。
_避免_：重试（那是同一回合内的事）、自动回复、追问轮

**任务（Task）**：
一段**连续的自动化执行**，从一次触发到停下，期间可含多个回合（一个首回合 + 零或多个追问回合）。
TUI 的一次 `Request::Prompt` 开启一个任务；`/loop` 的**每个 tick 各是一个独立任务**。
预算（如 `/goal` 的 turn 上限）以**任务**为单位计数，不跨任务累加。
_避免_：把 `/loop` 的连续多个 tick 当成同一个任务

**禁止歧义表述**：
「跨轮」一律禁用 —— 它可能指跨 round、跨 turn 或跨追问，是三件完全不同的事。
必须写成具体层次：

| 想说 | 写成 |
|---|---|
| 上一次模型调用 | 上一**轮**（round） |
| 上一次完整处理 | 上一**回合**（turn） |
| 上一次系统追加的回合 | 上一**追问** |
| 一个任务内的全部回合 | 本**任务**的全部回合（不要写「整条链」「跨回合」而不交代边界） |

同理禁用「跨回合」指代「跨 round」；若确指回合之间，写明它是否在同一任务内。

**终止原因（StopReason）**：
回合结束方式的分类：完成、达到最大轮数、被取消、被截断、无可见产出。终止是正常路径，通过回合结果表达，不通过错误表达。
**被截断**与「完成」并列，是**正常终止路径**而非错误：它来自模型侧的**输出预算限制**（provider 的 `finish_reason` 为 `length` / `max_tokens`），不是基础设施失败。
纯文本被截断时，回合**先回喂续写催促一次并继续**（ADR-0035），让模型从断点接着做完；**仍被截断**才以此收场。
**无可见产出**（`NoOutput`）与**完成**区分：完成表示「模型给出了可用的收尾」；无可见产出表示「回合结束了，
但模型既没有给出可见文本、也没有工具调用」（例如只输出了思考）。一次性模式据此返回非零退出码。
收场前**先催促重发一次**（`RunLimits::retry_empty_response`，默认开；仅对 `finish_reason = stop` 的
合法空回复生效，消耗一个轮）：仍空才判 `NoOutput` —— 它**不新增终止变体**，只把「有答复」的概率抬高。
_避免_：错误、失败（那是另一条通道）

**取消（Cancellation）**：
协作式的回合中止：只在步骤边界生效，不中断进行中的模型调用或工具执行；被取消的回合以终止原因收场。
_避免_：中断、强杀、abort

**压缩（Compaction）**：
回合**之内**、在轮边界把历史消息摘要化以腾出上下文空间的动作；它**不结束回合**，故与**追问**不同层。
注意两个同名词：**自动压缩**（接近上限时在轮边界自动触发）与 **`/compact` 命令**（用户手动触发，
同一份 `plan`/`execute` 实现；已非占位）。手动路径**不判触发阈值**（点了就压），且**回合中
经 `Boundary::Compact` 在下一个轮边界执行** —— 不走 `Request`（那只在回合之间被消费）。
_避免_：把压缩说成清空上下文（清空是 `/clear`：换新会话文件、旧文件保留；`/new` 是开下一段、不清屏）、压缩即失忆

### 会话

**恢复会话（resume）**：
切换到**另一条会话谱系** —— 与「重启后用 `--resume` 打开该会话」同构；运行期由 `/resume` 命令发起。
与 `/new` 相对：`/new` 在**同一会话谱系**里开下一段（只换会话句柄，不动内存中的历史）。
恢复是**替换而非合并**：`Wiring.session` 整体替换、内存里的旧 transcript 被丢弃，**磁盘上的旧文件不删**。
_避免_：激活、切换会话（未点明是换谱系还是同谱系续写）

**会话修复（SessionRecovery）**：
打开既有 JSONL 会话时的一次性规范化结果：为进程中断留下的悬空 `ToolUse` 合成错误
`ToolResult`，并统计无法解析而跳过的行。工具不会被重新执行；修复先原子落盘，摘要经
`Session::take_recovery` 只交给应用层一次。
_避免_：重放工具、自动恢复（未说明是修复消息配对）

**harness 输入（Harness Input）**：
harness 产生、**用户没说过**的会话输入：后台命令的完成结果、子 agent 的结果，以及为处理它们而
自动起的那个回合的占位消息。它们在会话里是 `Role::Harness`，⇒ 落盘与 `/resume` 回放据此
区分来源（回放时事件流已不存在，只能看角色）；发给模型时仍是 user 角色（适配器出站映射）。
与「注入」不同：**注入不落 session**，而 harness 输入是会话历史的正式成员。
与系统消息不同：`Role::System` 是系统提示一类的前缀，不是回合输入。
_避免_：系统消息（那是 `Role::System`，不进会话历史）、注入（那指轮内提醒，**不落 session**）

### 失败的双通道

**错误结果（Error Result）**：
工具把模型可理解的失败作为数据返回的 ToolResult，例如命令退出码非零、目标文件不存在。Loop 将其回喂模型，模型可自愈或换路。
_避免_：工具异常、ToolError（那是另一条通道）

**基础设施失败（ToolError）**：
工具无法产出任何可回喂的结果：适配器缺陷、结果无法构造。Loop 以错误终止回合。
_避免_：错误结果、业务失败

### 静态边界

**事件（Event）**：
已经发生之事的记录。只可观察，不可改变流程。
_避免_：Hook、回调

**Hook**：
参与生命周期决策的机制：只观察、转换数据或控制流程。与事件相对：事件面向过去，Hook 面向下一步。（后续阶段引入）

**Hookpoint（钩子点）**：
执行循环上一个**具名**的插入点。每个点**默认为空**；空置时循环行为与无 Hook 时逐字节一致。一个点可挂多个**处理器**。
_避免_：Hook（那是指整套机制，或单个处理器）

**Hook 处理器（Handler）**：
挂在某个 hookpoint 上、由 Hook 插件提供的一段逻辑。同一点上的多个处理器按序执行。

**Hook 插件（Hook Plugin）**：
在 Agent **初始化**时把处理器挂到各 hookpoint 的装配者。v1 只在启动期挂载，不支持运行期热插拔。

**组件（Component）**：
四类能力提供者：Model、Tool、Session、EventSink。

**Loop**：
决定「按什么规则推进」的执行策略；v0 只有 BasicLoop。

### 示例对话

> 开发者：bash 工具退出码非零，BasicLoop 是不是该报错退出？
> 领域：不。这是**错误结果**——模型能理解的失败数据，回喂模型让它修正命令。
> 开发者：那什么时候才算失败？
> 领域：工具连结果都构造不出来，即**基础设施失败**，才终止回合。
> 开发者：用户中途按了停止呢？
> 领域：那是**取消**：在步骤边界生效，回合以「被取消」这一**终止原因**结束——同样不是错误。
