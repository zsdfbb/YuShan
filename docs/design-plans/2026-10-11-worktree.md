# worktree CLI 设计计划

## 背景

- 并行 subagent 写同一棵树是本仓**长期记录的已知缺口**：ADR-0022 / ADR-0029 与
  `docs/design-final/coding-agent-tui.md:629` 都写「本仓无 branch/worktree、无沙箱 ⇒ 只能靠提示词约束」。
- 用户裁定：加一个 **CLI 子命令组** `ys-coding-agent worktree {create, attach, list, remove}`。
  `create` / `list` / `remove` 直套 `git worktree`；`attach` = **启动即绑定**（启动会话并把工作区绑到该树）。
- 因**工作区只在进程启动时选定一次** ⇒ 无中途切换 ⇒ 无工具、无斜杠命令、**零核心 crate 改动**。

## 设计

### 整体方案

- **唯一 git 调用点** = 新模块 `apps/coding-agent/src/worktree.rs`。
- **注入点**：`main()` 在 `Config::from_env()`（`main.rs:1207`）之后、skill 扫描（`main.rs:1224`）之前分流：
  - `create` / `list` / `remove` 在此**早退**（不需要 model / session / TUI）；
  - `attach` 把 `config.cwd` 换成树路径 —— 它在 `main.rs:1341` 派生 `cwd`、在 `:1342` 派生 `workspace`，
    分别喂 `build_system_prompt`（:1352/:1375）与 `build_tools` / `SubagentSetup` / `build_agent`，**两路全盖**。
- **落点**：`$HOME/.yushan/worktrees/<仓库的 HOME 相对路径，`/`→`-`>-<name>/`
  （`~/Develop/YuShan` + `feat` ⇒ `Develop-YuShan-feat`）。纯字符串、唯一、无 hash。
  仓库在 HOME 外 ⇒ 用绝对路径变换（文档写明）。`YUSHAN_WORKTREES_DIR` 覆盖根目录。
- **项目级配置**：`create` 时建软链 `<树>/.yushan` → 主仓 `.yushan`（主仓没有则跳过）。
  于是 skill 根、`.yushan/SYSTEM.md`、提示词的 `Current working directory` 三者天然自洽。
- **降级**：`attach` 遇非 git / git 不可用 / 树不存在 ⇒ **响亮警告 + 以共享工作区继续启动**；
  `create` / `remove` 是显式动作 ⇒ **硬失败**（非零退出 + 原因 + 退路）。
- **打印**：`create` 成功打 `worktree: <name>` 到 stderr（与 `session: <id>` 同侧）；
  会话结束在**既有退出行**追加同名行 —— 两个打印点：`main.rs:801`（`persist_single_turn`）与
  `main.rs:1194`（TUI 退出后）。**不需要新句柄**（工作区运行期不变）。

### 架构决策

1. **CLI 而非工具/斜杠命令**（用户裁定）：产物存在 ys 自己的目录下，用户不该被迫认识 git；
   创建是进程级副作用；覆盖面最广（用户 shell / 模型经 `bash` / skill / CI）。
2. **`attach` = 启动即绑定** ⇒ 「切换」变成装配问题 ⇒ 零核心 crate 改动。
3. **软链 `.yushan` 取代「项目根」概念**：实测 `build_system_prompt` 有 **20 个调用点**（18 在测试），
   软链方案下 `prompt.rs` / `config.rs` **完全不改**。
4. **`remove` 直套 `git worktree remove`**：天然**留分支、脏则拒删**，正是「只隔离不回流」要的策略。
5. **不引入** TTL / ledger / 自动清理 / `clap` / 新 crate 依赖。

### 数据流 / 接口变更

```text
argv → parse_args → Args{worktree: Option<WorktreeCmd>}
     ├─ Create/List/Remove → worktree::create/list/remove → 打印 → 早退（不建 runtime）
     └─ Attach(name)       → worktree::attach_target() → config.cwd = 树路径 → 既有启动路径原样
                            （失败 ⇒ 警告 + 保持 cwd 不变，继续共享工作区启动）
```

**无对外接口变更**：`crates/ys-protocol` 的 `Request` / `Outbound`、事件类型一律不动。

## 测试策略

### 测试合同（Phase 3 审查依据）

> 每条需求一条验收条款。所有条目**均可自动化**，无 `MANUAL_ACK_REQUIRED` 阻塞项。

#### N1: `create <name>` 建树

- **验收方法**: 临时 git 仓内跑 `worktree create feat` — 退出码 0、stderr 含 `worktree: feat`、
  `git -C <repo> worktree list` 含新路径、`git -C <repo> branch --list worktree-feat` 非空
- **优先级**: 必测

#### N2: `create` 免起名

- **验收方法**: 不带名跑 `worktree create` — 退出码 0、stderr 名字非空、对应目录存在；连跑两次名字不同
- **优先级**: 必测

#### N3: 非 git 仓硬失败

- **验收方法**: 临时**非** git 目录跑 `worktree create x` — 退出码非 0、stderr 含 `NotARepo` 类文案
- **优先级**: 必测

#### N4: `name` 校验

- **验收方法**: `worktree create ../evil`、`worktree create a/b` — 退出码非 0、stderr 含 `InvalidName`；
  且 `~/.yushan/worktrees` 下**没有**新增目录
- **优先级**: 必测

#### N5: `list`

- **验收方法**: 建两棵树后 `worktree list` — stdout 含两个名字与路径；无树的仓 ⇒ 空输出、退出码 0
- **优先级**: 必测

#### N6: `remove` 留分支、脏则拒删

- **验收方法**: 树内改一个文件后 `worktree remove <name>` — 退出码非 0 + 提示；`git commit` 后
  `remove` — 退出码 0、树目录消失、**分支 `worktree-<name>` 仍在**
- **优先级**: 必测

#### N7: `attach` 绑定工作区

- **验收方法**: 单测 `worktree::attach_target()` 返回树路径与主仓根（必测）；
  `#[ignore]` e2e 用凭证跑 `worktree attach <name> -p "<task>"` 断言 cwd（可推迟）
- **优先级**: 必测（单测）/ 可推迟（e2e）

#### N8: `attach` 降级

- **验收方法**: 非 git 目录 / 树不存在时跑 `attach` — 不 panic、stderr 含警告、以共享工作区继续
  （断言进程正常走到启动路径）
- **优先级**: 必测

#### N9: 退出行打印

- **验收方法**: worktree 会话跑 `-p` — stderr **同时**含 `session: <id>` 与 `worktree: <name>`；
  非 worktree 会话 ⇒ **只有** `session:`
- **优先级**: 必测

#### N10: 软链 `.yushan`

- **验收方法**: 主仓有 `.yushan/skills/x` 时 `create feat` ⇒ `<树>/.yushan` 是指向主仓 `.yushan` 的符号链接；
  主仓无 `.yushan` ⇒ 不建链、不报错
- **优先级**: 必测

#### N11: `parse_args` 子命令

- **验收方法**: `parse_args(&["worktree","create","x"])` ⇒ 对应枚举；`worktree` 后跟未知动词 ⇒ `Err`；
  **非 flag 首 token 的既有静默 Interactive 行为不回归**
- **优先级**: 必测

#### N12: 既有行为不回归

- **验收方法**: `cargo test --workspace` 全绿；`-p` / `--json` / `--resume` 既有测试不动
- **优先级**: 必测

### 测试框架与命令

- 单元与集成: `cargo test -p ys-coding-agent`
- 全量回归: `cargo test --workspace`
- Lint: `cargo clippy --all-targets`
- ⚠️ **本仓无 `tempfile` 依赖、且此前零 git 调用**：测试须自造临时目录
  （`std::env::temp_dir()` + `process::id()` + 进程内原子序号，照 `main.rs:1525` `unique_tmp_dir` 的先例）
  并真调 `git init` / `git -C ...`；改环境变量的测试**必须**走 `crate::test_env::env_lock()` + `EnvRestore`。
- 需凭证的 e2e 标 `#[ignore]`（照本仓既有做法，如 `cargo test -p ys-coding-agent e2e -- --ignored`）。

## 风险与注意事项

- **测试真调 git 是本仓第一次**：注意并行安全（临时目录名含 pid + 原子序号），
  且改了 `HOME` / `YUSHAN_WORKTREES_DIR` 的测试必须 `env_lock()` + `EnvRestore`。
- **软链在 `.yushan` 不存在时跳过**，不报错（主仓没有项目级配置是常态）。
- **仓库在 HOME 外**的落点规则（绝对路径变换）须在文档写明，属罕见路径。
- **首次 `attach` 首轮 prompt cache miss**（每个 worktree 一份提示词前缀）—— 已知代价，非缺陷。
- `create` 遇同名陈旧 registration（用户 `rm -rf` 过树）⇒ 先 `git worktree prune` 重试一次。
