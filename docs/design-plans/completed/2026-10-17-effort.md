# `/effort` 思考档位命令 设计计划

## 背景

coding-agent 目前只能解析模型**返回**的 `reasoning_content`（`ModelEvent::ThinkingDelta`），**没有任何请求侧思考控制**：`ModelRequest`、`ChatCompletionRequest`、`OpenAICompatibleConfig` 均无 `reasoning_effort` / `thinking` 字段（全仓 grep 零命中）。用户需要一个 `/effort` 斜杠命令，在会话内控制模型的思考级别。

该设置与 `/model` 同属「下一回合生效的模型设置」，但不切换模型，而是给请求附加 provider 原生的思考参数。生效粒度为回合（与 ADR 的 turn 粒度一致）。

## 已确认决策

| # | 决策 |
|---|---|
| D1 | **随会话持久化**：写入 `SessionMeta.effort`；`--resume` / `/resume` 恢复；`/new` 不重置（同 `thinking_visible`） |
| D2 | **Pi 全套档位**：`off` / `minimal` / `low` / `medium` / `high` / `xhigh` / `max`；额外 `default` = 清除设置（请求不发任何思考字段） |
| D3 | **不支持时提示 + 使用可接受参数**：设置照常保存；已知无可接受参数（MiniMax）时提示并**不发送**思考字段；其余 provider 按方言发送 |

## 设计

### 命令语义

```
/effort                 本地显示当前档位与用法（不发 Request）
/effort <level>         保存并重建模型，下一回合生效
/effort default         清除设置（恢复 provider 默认）
/effort <非法值>        本地用法提示，状态不变
```

- 生效粒度 = 回合；`RuntimeContext.model` 在整回合内固定（与 `/model` 相同）。
- 子 Agent 与压缩/摘要调用经 `Config` 工厂重建模型，**自动继承**当前档位。
- `-p` / `--json` 没有斜杠命令；恢复会话时仍会从会话 meta 读到 `effort` 并应用。

### 单一数据源

`ys-core::EffortLevel`：纯枚举，`Off / Minimal / Low / Medium / High / XHigh / Max`，实现 `FromStr` / `Display` / serde；无 tokio、无 provider 知识。`Option<EffortLevel>::None` = 未设置（`default`）。

### 数据流

```
TUI /effort high
  └─ Request::SetEffort { effort: Some(High) }
       └─ app_loop match → capabilities::set_effort
            ├─ config.effort = Some(High)
            ├─ config.build_model() → wiring.set_model
            └─ 下一回合生效（含 subagent / compact / summarize）
                 └─ adapter::translate_request 按 ProviderCompat 方言写 wire 字段
                      └─ SessionMeta.effort 回合末落盘；resume 时还原并重建
```

### provider wire 方言（`ProviderCompat.reasoning_dialect`）

| 方言 | provider | `off` | 档位 |
|---|---|---|---|
| `DeepSeek` | `deepseek` | `thinking:{type:"disabled"}` | `reasoning_effort:<level>` + `thinking:{type:"enabled"}`（官方文档同发） |
| `OpenCodeGo` | `opencode-go` | `thinking:{type:"disabled"}` | **只** `reasoning_effort:<level>`（该网关拒绝同时出现两字段） |
| `OpenAiEffort` | `custom` / env 直连 / 未知 | `reasoning_effort:"none"` | `reasoning_effort:<level>` |
| `None` | `minimax` | 不发任何思考字段 | 不发任何思考字段（命令输出提示） |

`level` 的 wire 拼写为 `minimal|low|medium|high|xhigh|max`；服务端折叠（如 DeepSeek `medium→high`）由 provider 负责。`default`（`None`）时所有方言都不发字段。

### 接口变更

- `ys-core::EffortLevel`（新增）：`FromStr` 严格解析，`Display` 给规范拼写。
- `ys_protocol::Request::SetEffort { effort: Option<EffortLevel> }`（新增变体）。
- `ys_session::SessionMeta.effort: Option<EffortLevel>`，`#[serde(default)]`。
- `OpenAICompatibleConfig.effort: Option<EffortLevel>`；`ProviderCompat.reasoning_dialect`。
- `ChatCompletionRequest` 新增 `reasoning_effort: Option<String>` 与 `thinking: Option<ThinkingToggle>`，均 `skip_serializing_if`。
- `Config.effort: Option<EffortLevel>`；`CodingView.effort: Option<EffortLevel>`。
- `finalize_turn_meta` 增加三态参数：`None` = 不写（`-p` / `--json`），`Some(Option<EffortLevel>)` = 写入（TUI，含清除）。

### 关键不变量

- `config.effort` 是运行期真值；`wiring.model` 是当前回合所用模型。`set_effort` 重建失败时 `wiring.set_model(None)`（照 `set_model` 的 E1 契约）。
- `OpenCodeGo` 方言**绝不**同时发送 `thinking` 与 `reasoning_effort`。
- `/new` 不重置 effort；`/resume` 从目标 meta 还原 effort 并重建模型。
- 旧 JSONL 缺 `effort` 键 ⇒ `None`，不得反序列化失败。

## 测试策略

### 测试合同（Phase 3 审查依据）

#### N1: EffortLevel 契约
- **验收方法**: `cargo test -p ys-core effort` — 七个档位 + `default` 的 `FromStr`/`Display`/serde 往返；非法值 `FromStr` 返回 `Err`。变异：改一个 wire 拼写 ⇒ 测试变红。
- **优先级**: 必测
- **验收人**: review subagent

#### N2: 协议往返
- **验收方法**: `cargo test -p ys-protocol` — `SetEffort { Some(High) }` 与 `{ None }` 序列化/反序列化往返；既有变体仍可反序列化。
- **优先级**: 必测
- **验收人**: review subagent

#### N3: 会话 meta 兼容
- **验收方法**: `cargo test -p ys-session` — 含 `effort` 的 meta 往返；旧 JSONL 首行无 `effort` 键 ⇒ `None`；首行重写保留该字段。
- **优先级**: 必测
- **验收人**: review subagent

#### N4: provider wire 映射
- **验收方法**: `cargo test -p ys-model-openai-compat` — 四方言 × {off, 每个档位, default} 的请求体断言；`OpenCodeGo` 下 `thinking` 与 `reasoning_effort` 绝不同时出现；`default` 下两字段皆无；`minimax` 不发送。
- **优先级**: 必测
- **验收人**: review subagent

#### N5: app 能力与持久化
- **验收方法**: `cargo test -p ys-coding-agent` — `set_effort` 更新 `config.effort`、重建模型、输出确认；无凭证时 `wiring.set_model(None)`；MiniMax 输出提示；`resume_session` 从 meta 还原 effort；回合末 meta 写入 / 清除 effort。
- **优先级**: 必测

#### N6: TUI 命令
- **验收方法**: `cargo test -p ys-tui-coding` — 命令表 14 条；`/effort high` → `SetEffort{Some(High)}`；`/effort default` → `SetEffort{None}`；无参 → 本地显示；非法值 → 用法提示；`/status` 含 effort。
- **优先级**: 必测

#### N7: app_loop 分发
- **验收方法**: `cargo test -p ys-coding-agent app_loop` — `Request::SetEffort` 被穷尽 match 处理并产出 `Output`；`/new` 不重置；`/resume` 跟随目标 meta。
- **优先级**: 必测

#### N8: 全量回归与文档一致性
- **验收方法**: `cargo test --workspace` + `cargo clippy --all-targets` + `bash scripts/doc-consistency.sh` — 全部退出 0。

- **验收方法**: 配置真实凭证启动 TUI；`/effort high` 后发一条普通提示，确认无 400；`/thinking on` 观察思考增量；`/effort off` 后确认思考增量消失（若模型强制思考则记录实际行为）；退出后 `--resume` 同一会话确认档位恢复。
- **优先级**: MANUAL_ACK_REQUIRED

## 风险与注意事项

- **方言未实测**：`opencode-go` 对顶层 `reasoning_effort` 的接受度、DeepSeek 工具循环是否要求回传 `reasoning_content`，需 N9 手测确认。映射集中在 `ProviderCompat` 一处，调整不影响其它层。
- `off` 在部分网关可能没有真正的 disable 语义；N9 记录实际行为。
- `OpenAICompatibleConfig` 新增字段会要求 13 处结构体字面量补字段；测试侧可用 `..Default::default()`，生产侧显式传 `cfg.effort`。
- **不做**：`-p` / `--json` 的 `--effort` flag、`YUSHAN_EFFORT` 环境变量、自动路由、能力发现、请求被拒后的自动降档重试。
