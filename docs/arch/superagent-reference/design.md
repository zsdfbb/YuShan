# super agent 的底层与核心 — 设计起点

> 性质：**设计起点**。不是「我们可以借什么」的清单，也不是差距台账。
> 本文先给 super agent 的分层，再把注意力收缩到底层与核心那两层，最后收敛到**唯一要开口子**的地方。
> 外部参照是 `tmp/dsh-superagent-prototype`（DeepSeek Harness 上的 research prototype，
> **未被版本控制跟踪**）的 `docs/000`–`docs/008`，引用方式见 §7。
> 日期：2026-11-07

---

## 0. 一句话

**super agent 不是「更强的 agent」，是把 agent 放进一个更大的执行结构里。**
那个结构的地基只有两块砖：**回合能被系统推进**、**事实能跨回合存活**。

⇒ 本仓要设计的不是 super agent，是**这两块砖的规格**。上层砌什么楼，不该由我们定。

⚠️ 这条区分决定了本文的写法：凡「产品该怎么做」的讨论一律不进设计，只留一句「属 L3+」。
上一版文档按「可借 / 不可借」组织，容易让人以为我们要照着原型做一个产品 —— 那是错的切入点。

---

## 1. 分层

分层的判据只有一条：**这一层决定的东西，能不能脱离具体业务成立。**
能 ⇒ 属于运行时（我们）；不能 ⇒ 属于上层产品。

| 层 | 决定什么 | 能脱离域吗 | 原型里的名字 | 本仓 |
|---|---|---|---|---|
| **L0 回合层** | 何时有「下一步」；一步到哪停 | **能**，纯机制 | turn / Session | **就是这一层** |
| **L1 事实层** | 系统怎么知道「发生了什么」 | **能**，纯机制 | Report、Ticket stage、`inputsRead` | 有原语，缺归属与寿命 |
| **L2 边界层** | 一条入站消息是**控制**、**上下文**，还是**一次新授权** | 半能：**分类**是机制，**判据**是域 | `Boundary` 的各种格 | 格已留，语义归上层 |
| L3 工作层 | 一个工作何时开始、何时算完 | 不能，域 | Ticket / Assignment / Mandate | **不做** |
| L4 接入层 | 事件从哪来、写到哪去 | 不能，域 | Source / Channel | **不做** |
| L5 人机层 | 人怎么介入 | 不能，域 | Panel / Attention | **不做** |

**核心在 L1→L2 那条线上**：机器把事实交上去，域拿它做判断。
我们的责任是让这条线**够宽**（事实够全、够久、有归属），同时**够窄**（不替域做判断）。

## 2. 核心：两条不变量 + 一条纪律

### 2.1 不变量 A — 回合可续

**它的表述**：工作是边界，回合只是工作的一个片段。工作何时结束由域规则判定
（PR 都关了 / 人说不做了 / 授权失效），不是模型宣布完成
（`003-execution.md` § How a Ticket ends）。一轮结束只是「报了件事」，不等于工作结束。

**我们的现状**：`Completed` 自身无文档注释，它的定义（「模型给出了可用的收尾」）出现在
`NoOutput` 的对比说明里（`crates/ys-core/src/stop.rs:21-22`；枚举本体在 `:5`）。六个变体（`Completed` /
`MaxRounds` / `Cancelled` / `Truncated` / `Failed` / `NoOutput`）全部在描述**这一回合怎么结束的**，
没有一个在描述**工作到哪了**。

**差距的本质**不是缺功能，是**语义层级不同**：
我们只有「语义完成」（模型说完了），它多一层「工作完成」（域判完了）。
中间缺那句「系统判定还没完 ⇒ 再推一次」。

**已经走了一半**：`bash_bg` 完成与子 agent 完成都会**自动起一个新回合**
（`Wake::BackgroundReturned` / `Wake::SubagentReturned`，`apps/coding-agent/src/app_loop.rs:402`
的 `select!` 臂 → `:413` 的 `Wake::SubagentReturned` 分支）。
但那两条的触发源都是「某个后台任务干完了」，不是「工作还没完」。

### 2.2 不变量 B — 事实可跨回合存活

**它的表述**：把输入状态拆成三段**可判定的事实**，而不是一个状态机：

| 事实 | 判定依据 |
|---|---|
| 已送达 | 到了会话，等某一步取用 |
| 已读 | 被某一步取进历史，**且随后发生了报告或回合结束** |
| 已处理 | 报告 / 退回 / 下一份报告覆盖 |

外加一条兜底：工作结束时，**未读且未被「确认 / 回答 / 退回」的消息全部退回上游**
（`003-execution.md` § Follow-ups and context Threads、`007-architecture.md` § Engine）。
「已读但无动作」（一句道谢）不退回。状态本身是**从这些事实推导**的
（`ticketStage` 是一张 first-match-wins 的表，`007-architecture.md` § Engine），不另存。

**我们的现状**：原语齐全 —— `SubagentOutcome { stop_reason, diagnostic, usage }`
（`crates/ys-tool/src/subagent.rs:28`）、`StopReason` 里把 `Failed`（故障）与
`Cancelled`（意图）分开（`crates/ys-core/src/stop.rs:11-19`）、`AgentEvent::DeferredResult`
与 `UserMessage` 分开（`crates/ys-event/src/event.rs:43`）。**规则是对的。**

**差距的本质**：事实的**归属**与**寿命**都绑在了最短命的那个单位上。
`PendingResults` 是内存 `Vec`（`apps/coding-agent/src/subagent.rs:296`），进程退即丢；
表满 32 条（`:85`）就**淘汰最旧一条**（`:334`）；且它进程级、不区分会话
（同类边界见 `docs/TODO.md` §D）。

⇒ 「事实可跨回合存活」在我们这儿只对**进程内**成立。

### 2.3 纪律 — 上下文流动 ≠ 权限流动

**它的表述**：订阅线程上的消息**作为上下文**扇出给工作，明确「绕过准入门，不授予任何新权限」
（`002-authorization.md` § Subscriptions）。于是「继续既有工作」是**零新决策**的
（`002-authorization.md` § Resume and stop）—— 上下文自由流动，权限一动不动。

**我们的现状**：这条**已经做对了，而且理由与它一致**：

- 入站分格：`Boundary::{Steer, Deferred, Compact, Abort}`
  （`crates/ys-protocol/src/boundary.rs:12` 的枚举本体）—— 控制与上下文各走各的格；
- 出站分格：`AgentEvent::UserMessage` 与 `DeferredResult` 必须分开，理由写在
  `crates/ys-event/src/event.rs:43` 起的那段文档注释里：**别让用户看到自己没说过的话
  被画成自己的发言**。

⇒ 这一条不需要改，需要的是**写进契约**（§5）：让上层知道这个区分存在、可以依赖。

## 3. 对账：四条核心规则的对位

上一版把这里写成「差距」，是错的。**四条核心规则里三条我们已经落地**，只是从没跟外部实现对过账。

| # | 规则 | 它的表述 | 我们的落点 | 状态 |
|---|---|---|---|---|
| ① | 入站分「控制 / 上下文」 | 准入门 vs 订阅扇出 | `Boundary` 四格分离 | **已有** |
| ② | 报告是结构化事实，不是一段话 | 结构化 `Report`；**明确拒绝**从自由文本推断「在等人」（`001-domain.md` § Rejected concepts） | `SubagentOutcome` + `StopReason` 六变体 | **已有** |
| ③ | 干活的东西 ≠ 记账的东西 | Ticket ≠ Assignment ≠ Session | Agent 无状态（ADR-0010）、Session 归接线器 | **已有** |
| ④ | 观察与控制分两条路 | 事件只观察 | 本仓硬不变量：Event 观察，Hook 控制 | **已有**（还是硬约束） |
| ⑤ | **工作何时算完，判据在代码里** | 域规则判结束 | 只有回合层的「语义完成」 | **缺**，且只缺这一条 |

⇒ 结论应当改写为：**我们不是能力不足，是一门没开的门**。

## 4. 唯一的开口

### 4.1 缺的那一格

`Boundary` 今天只有 `Steer` / `Deferred` / `Compact` / `Abort`
（`crates/ys-protocol/src/boundary.rs:12` 的枚举，`:34` 的 `Abort` 为末项）。逐条对位：

| 现有的格 | 语义 | 能不能冒充「工作还没完」 |
|---|---|---|
| `Steer` | 人（或上层）在回合中插一句话 | **不能**：语义是「有人说了一句话」，且会被渲染成人的发言 |
| `Deferred` | 某个后台任务的**结果回来了** | **不能**：语义是「产出物到达」，塞进去是冒名顶替 |
| `Compact` | 手动压缩 | 不能 |
| `Abort` | 中止 | 不能 |

⇒ **没有一个入口是给「系统因为工作没做完而再推一次」的。**

### 4.2 为什么这是核心而不是功能

上层要建模「工作」，就必须能说「还没完，继续」。没有这一格，上层只剩两条退路，两条都坏：

1. **让模型一直跑**（长回合模拟工作）⇒ 上下文单调增长、成本不可控、
   中途状态不可观察（正是 ADR-0065 拆掉同步派发时反对的那个黑箱）。
2. **自己在外层起进程 / 起会话** ⇒ 跨进程丢上下文，且我们承诺的「绝不丢失」管不到它。

⇒ 这一格不开，**L2 及以上全部落不了地**。它才是本仓对 super agent 的真正贡献点。

### 4.3 设计要点（先立契约，不选实现）

下面五条是**约束**，不是方案。具体形状须单独立 ADR。

1. **它描述的是「推进」，不是「内容」。** 内容由上层给（要说什么）；「再推一次」这个
   决定必须由系统发出。二者不可合并成一个格 —— 合并后语义又回到 `Steer`。
2. **它必须能跨回合存活。** 不变量 B 对入站方向同样成立：一条「还没完」在回合结束时
   不许丢。⇒ 需要一个 app 侧的、**跨回合**的队列（今天没有；`docs/TODO.md` §B）。
3. **它不得绕过 `Abort`。** 取消优先于推进 —— 否则「停不下来」。
4. **它不该知道「为什么还没完」。** 理由属于 L3。我们只负责把「该推一次」这个事实送达，
   由上层在内容里说明理由。这是「够窄」那一半。
5. **它必须以结构化事实的形式到达模型**（承 §3 规则②），不是一段自由文本 ——
   否则又变成「模型猜自己该不该继续」。

### 4.4 判据

做完这一格，下面这句话必须成立：

> 上层可以在回合结束后、进程不重启的前提下，让这个 agent 带着原上下文再跑一轮，
> 并且能解释「为什么它是系统推的，不是人说的」。

## 5. 对上层承诺的契约（L1→L2 这条线）

| 我们保证 | 我们不保证 |
|---|---|
| 回合可被系统推进（§4 完成后） | 一个「工作」的生命周期 —— 状态机属于 L3 |
| 每条入站消息**可分辨**是控制还是上下文 | 谁有权发一条控制 —— 授权属于 L3 |
| 结构化终止原因（`StopReason`），故障与取消分开 | 终止原因的业务含义 |
| 结果**至少送达一次**（ADR-0051 口径：可选重复，绝不丢失） | **恰好一次** —— 去重键由上层定 |
| 事件流可观察，且与执行互不影响 | 持久化域、面板、通知 —— L5 |

⚠️ 两条今天**还不成立**，落在 §6 的配套项里：跨回合/跨进程的「绝不丢失」、
以及「进程退后还有机会投」。契约现在只覆盖进程内。

## 6. 非核心的配套项

这些是真的、该做，但**不是核心** —— 它们是让核心可用的规约。列在这里是为了不把它们
和 §4 混为一谈。

| 项 | 今天的形态 | 为什么不是核心 |
|---|---|---|
| 结果落盘 | 内存 `Vec`，满 32 条淘汰最旧（`apps/coding-agent/src/subagent.rs:296`、`:334`） | 落盘是寿命问题；寿命服务于不变量 B，本身不产生新语义 |
| 会话归属 | 进程级、不区分会话 | 同上 |
| 单回合模式补投 | `-p` / `--json` 回合结束即失效：落点照绑（`apps/coding-agent/src/main.rs:2027`），但「本回合专属的边界源」随函数返回销毁，结果落表后**没有下一回合可补投**（同一处注释 `:2029-2032`） | 同上 |
| 准入闸 | 派发次数超限即 `Err`、不排队（`take_dispatch_slot`，`apps/coding-agent/src/subagent.rs:1310`）；无运行期并发闸 | 是资源管理，不是执行语义。⚠️ 做的时候必须区分**准入拒绝**与**运行失败**（槽满不算故障），照 `007-architecture.md` § Effects 的 `Later` |
| 健康统计 | 无；连续失败无汇总 | 可观察性的配套 |
| 状态板 | `LiveSubagents::count` 是 `#[cfg(test)]`（`apps/coding-agent/src/subagent.rs:524-525`） | 价值取决于有没有人看。**先有 §4 的事实可推导，它才有意义** |

## 7. 明确不做（L3–L5）

| 不做 | 理由 |
|---|---|
| `Policy` / `Mandate` / 准入表 / accept mode | 撞本仓硬约束「不做安全，沙箱/隔离/权限/审批/多租户由上层解决」。**不是难，是义务**：长出授权就等于对多租户安全负责 |
| 域级两阶段判定（确定性门 + 模型研判） | 判断归上层。我们只送事实 |
| 常驻服务、SQLite 持久域、outbox 回执、schema 迁移 | 我们是库 + 单进程 CLI |
| 动态插件注册 | ADR-0021 有意推迟 |
| 子 agent 嵌套（深度 >1） | 子表 `General` 即基础 9 元（`apps/coding-agent/src/subagent.rs:1409` 的 `child_tools`），无二次派发工具 ⇒ 深度恒 1。**是选择**：深度 >1 会把「谁占槽位」变成二维，而我们连一维的闸都还没有 |
