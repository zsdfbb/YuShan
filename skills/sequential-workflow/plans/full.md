# Full — 标准完整流程

## 适用场景
- 新功能开发
- 中型以上改动（涉及多个文件、目录）
- 需要完整的 Write → Execute → Finalize 闭环
- 设计已由 `arch-*` 系列产出并核实通过 → 适用自动放行（C.3 六条判据全绿即免签字）

## 执行阶段

```
Phase 2  Write:    写 design-plan + exec-plan
Phase 3  Execute:  基线 → 合并单元 → 波次并发（≤3）→ 分档 review（deep 独立 / shallow 批量）
Phase 4  Finalize: 更新 design-final/ + 归档
```

## 并发说明

- 单元数 ≥4 时波次并发的收益最大；少于 3 个单元时并发没有意义
- 同波单元的文件集必须互不相交；相交则合并为一个单元，或把后者顺延到下一波
- 单个合并单元控制在 ≤5 文件 / ≤10 分钟工作量（防挂策略上限）
- 失败隔离：某单元失败只标记它，同波其他单元继续；其下游跳过，留给 Phase 5
