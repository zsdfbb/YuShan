# Arch Explore — 架构探索与需求澄清

## Quick start

当你说"帮我看看 xxx 的架构"或"分析一下这个模块的现状"时，启动本 skill。核心流程：

1. 代码/文档探索：读关键入口、识别依赖、理解架构风格
2. 约束发现：技术约束、性能约束、演进约束、组织约束
3. 需求澄清 + 产出：Scope 界定、关键场景、未澄清问题

**产出文件**（写入 `docs/arch/<需求名>/`）：
- `context.md` — 架构上下文文档

## Workflow

### Step 1: 代码/文档探索

系统化地阅读和理解目标模块。

- 读关键入口文件和接口定义
- 识别外部依赖和上下游
- 理解当前架构风格和约定
- 记录核心抽象和关键数据流

### Step 2: 约束发现

从四个维度收集约束：

| 维度 | 检查项 |
|------|--------|
| 技术约束 | 语言、运行时、已有框架、不可替换的依赖 |
| 性能约束 | QPS/TPS、P99 延迟、内存上限、磁盘/网络预算 |
| 演进约束 | 向后兼容要求、多版本维护、迁移路径 |
| 组织约束 | 团队规模、维护能力、发布时间线 |

### Step 3: 需求澄清 + 产出

澄清设计目标和范围：

- [ ] Scope 界定（做什么 + 不做什么）
- [ ] 关键场景（成功路径）
- [ ] 异常/边界场景
- [ ] 质量目标（可用性、延迟、吞吐目标）
- [ ] 未澄清的问题列表

**写入 `docs/arch/<需求名>/context.md`**

### context.md 模板

```markdown

[边界描述、对外接口、调用者]

[关键结构体/类/接口]

### 关键数据流

[核心交互路径]

### 外部依赖

| 依赖 | 用途 | 版本 | 备注 |
|------|------|------|------|

## 约束

- 技术：...
- 性能：...
- 演进：...
- 组织：...

## 需求范围

### 范围内

- ...

### 范围外（明确不做的）

- ...

### 关键场景

- 场景 1：...
- 场景 2：...

## 未澄清问题

- [ ] 问题 1
- [ ] 问题 2
```
