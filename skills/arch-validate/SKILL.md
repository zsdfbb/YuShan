# Arch Validate — 架构质量分析

## Quick start

当你说"review 一下这个设计"或"分析 xxx 的可维护性"时，启动本 skill。核心流程：

1. 界定分析范围和分析维度
2. 多维度分析（可行性 / 可维护性 / 可理解性 / 性能与可靠性）
3. 输出综合报告

**产出文件**（写入 `docs/arch/<需求名>/`）：
- `review.md` — 质量分析报告（各维度绿/黄/红、风险排序、改进建议）

## Workflow

### Step 1: 范围界定

确认分析对象和关注维度。

检查清单：
- [ ] 分析对象：设计方案文档 / 代码模块 / 整个子系统
- [ ] 关注维度：全量 / 选定维度
- [ ] 是否有现成的 `design.md` 或 `context.md` 可以参考

### Step 2: 多维度分析

各维度说明（详细检查清单见 [REFERENCE.md](REFERENCE.md)）：

**可行性**
- 技术可实现性
- 依赖成熟度与风险
- 实现周期评估

**可维护性**（含基础软件重点）
- 模块边界与关注点分离
- 接口稳定性与演进策略
- 测试难度
- 错误传播与处理完整性 ← 基础软件
- 并发安全性（锁、竞态、死锁） ← 基础软件
- 资源管理（泄漏路径、生命周期） ← 基础软件

**可理解性**
- 概念一致性
- 抽象层次匹配
- 文档完整度
- 新人上手成本

**性能与可靠性**（可选深度分析）
- 性能模型：延迟预算、吞吐瓶颈
- 故障模式：单点、级联、降级策略
- 可观测性：metrics/tracing/logging 覆盖

### Step 3: 综合报告

输出格式：
- 各维度绿/黄/红判断
- 风险排序（影响 × 可能性）
- 改进建议（分层：**易修复** / **需讨论** / **架构级**）
- 写入 `docs/arch/<需求名>/review.md`
