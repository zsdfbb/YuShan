> 日期：2026-09-21

> 权威设计：[`../arch/skills/design.md`](../arch/skills/design.md)；上下文：[`../arch/skills/context.md`](../arch/skills/context.md)
> 执行计划：[`../exec-plans/2026-09-21-skills.md`](../exec-plans/2026-09-21-skills.md)
> 性质：**新增能力的设计**。本文件只讲 skills；压缩耦合修正（决策 E）是它的**附带修正**，不是本计划的主题。

## 1. 背景与动机

**需求**：让 coding agent 复用**已存在的 56 个 Claude Code `SKILL.md`**（用户自行软链进
`~/.yushan/skills`），走**渐进式披露** —— `name` + `description` 常驻系统提示，正文按需进上下文。

**为什么值得做**：这批 skill 是**用户已经写好、正在用**的资产。复用率是首要质量目标；
启动开销次之。而它们**格式与 Claude Code 一致**（用户明确要求），故设计上以「格式兼容、
机制可不同」为准则。

**为什么不是「加个 skill 工具」**（这是本设计最反直觉、也最关键的一条）：见 §3.1。
一句话 —— **模型自主路线上，`read(绝对路径)` 与 `skill(name)` 都是恰好 1 次 tool
round-trip，专用工具买不到任何东西**，却要付 10 处连锁点 + 每轮永久 ~220 token。

**为什么必须先做压缩耦合修正**：56 条 description 实测 **18,226 B ≈ 9.6k token/轮**。
而 `basic.rs` 的压缩触发**只算 session 消息，不算 system prompt、也不算 tools** ——
9 工具时缺口 ≈1.1k（可忽略），skill 目录入场后缺口变成 **~9.6k 且不被任何阈值看见**。
不修，则压缩**系统性晚触发**，小窗口（8k/16k）下直接把请求顶出窗口。

## 2. 概念边界（必须先分清）

| 概念 | 定义 | 本计划中的角色 |
|---|---|---|
| **skill** | 一个含 `SKILL.md` 的目录；frontmatter（`name`/`description`/…）+ markdown 正文 | 被扫描、被嵌入提示、被激活的对象 |
| **catalogue** | 启动期由全部 skill 派生的**目录段**（`<available_skills>` 文本 + 条目 + 省略计数） | 进系统提示的**唯一** skill 产物 |
| **激活** | 把某条 skill 的**正文**送进上下文 | 两条路：模型自主 `read` / 用户 `/skill-name` |
| **展开**（expand） | 把 `/skill-name args` 这条**文本**重写成带正文的 user 消息 | 只发生在 app 层，TUI 不做 |

与本功能相邻的两个概念要分清：

- **skill ≠ 工具**：skill 是**数据**（启动期静态扫描），不是运行期可增删的能力。
  这直接来自「**工具面必须恒定**」不变量（工具面抖动会废掉 prompt cache）。
- **`/skill-name` ≠ 新 `Request` 变体**：它是**展开型命令** ——
  产物是文本，走与纯文本输入**完全相同**的路（沿用已作废前身文档
  `tui-repl-context.md:266-296` 的主张，ADR-0019 决策 2 关闭 Q18）。

## 3. 设计

### 3.1 形状：零新工具、零新协议变体、零新依赖

三条「零」是本设计的骨架，逐条对应一个**反向论证**：

| 零 | 反向论证 |
|---|---|
| **零新工具** | 模型调 `read(绝对路径)` 与调 `skill(name)` 都是 1 次 round-trip ⇒ 工具路线**净收益为零**。而代价可数：`toolset.rs` 的连锁点（`EXPECTED_ORDER` / `vec!` / 3 处 `assert_eq!(len,9)`）、`prompt.rs` 的 snippet + guideline + 逐字守卫、一个 `Tool` 实现 + `build_tools` 签名改动、**每轮永久 ~220 token**。 |
| **零新协议变体** | 新 `Request` 变体除协议 + serde + 测试外，还会**分叉 `app_loop` 的回合启动路径** —— `turns += 1` / `set_context_window` / `run_turn` 全在 `Request::Prompt` 臂里。复用 `Prompt` 让「展开型命令」与「纯文本输入」走同一条路。 |
| **零新依赖** | ADR-0015 否决 `ignore`/`regex`/`globset`/`walkdir`；`serde_yaml` 已被上游归档弃用。实测 56 条 frontmatter 只有 4 种写法 ⇒ **自写 ~60 行逐行状态机**可行（**不用正则**）。 |

**为什么落 app 层而不是新 crate**：skill 是**产品概念**（启动期扫描 + 提示词拼装），不是
运行时能力。前身文档把 `ys-skill` crate 列为「不做」，本设计**维持该裁决**。
`ys-tui-coding` 只拿到 `SkillEntry`（纯数据），**仍不认识任何 app 类型**（编译器强制）。

### 3.2 数据流

```
【启动期 · 一次 · 此后冻结】
  roots = [ <cwd>/.yushan/skills , ~/.yushan/skills ]        ← 显式路径；顺序即优先级
  skills::scan(roots)                     ← 每 root 一层 readdir + 每 SKILL.md 有界读(前 4KB)
      → (Vec<SkillEntry>, Vec<String>诊断)
  skills::catalogue(raw, Budget)          ← 纯函数、无 IO：去重(project > user) → 排序 → 预算
      → Catalogue { lines, entries, omitted, bytes }
  prompt::build_system_prompt(cwd, specs, &catalogue)   ← 末尾追加 <available_skills>
  AgentBuilder::system_prompt(…)                        ← 冻结（无 setter —— 对本设计是好事）
  resolve_limits(…) → RunLimits.fixed_prompt_tokens     ← 压缩耦合修正（见 §3.5）
  view::build_view(…) → 读 cfg.skills → CodingView.skills / skills_omitted   ← `/` 浮层唯一数据通路
                                                     （**签名不改**：`build_view` 已收 `cfg: &Config`）

【路线 1 · 模型自主】（1 次 tool round-trip）
  模型读 <available_skills> 的 name + description + location
      → 调既有 read(path = location 绝对路径)            ← ReadTool 是 workspace.join(path)，
                                                           绝对路径替换基址 ⇒ workspace 外可读
      → 正文（带行号）进 ToolResult → 进上下文（transcript 可见）
  正文引用的 references/ 相对路径 → 按 skill 目录解析（提示句逐字写在目录前言里）

【路线 2 · 用户显式 /git-status <args>】（0 次额外 round-trip）
  events.rs::submit → commands::parse(text, &app.view.skills)
      → Action::Request(Request::Prompt("/git-status <args>"))   ← 零协议改动
  app_loop.rs  Request::Prompt 臂（唯一改动 ≈2 行）：
      skills::expand_invocation(text, &config.skills)
      → <skill name="…" location="…">\n{SKILL.md 原文}\n</skill>\n\n{args}
      → 走既有的 turns += 1 / set_context_window / run_turn（**不分叉回合启动路径**）

【-p / --json】
  main 里对 task 调同一个 expand_invocation ⇒ 三模式一致
```

**两条路线给模型的都是 SKILL.md 原文**（路线 1 多行号与截断提示），因此 app 侧**只需要一个
`expand_invocation`**，不需要第二个「剥 frontmatter」函数。正文**含 frontmatter**（比 CC 多 ~150 B），
这是**有意接受**的代价 —— 换掉一个需要长期维护的第二个解析器。

### 3.4 frontmatter 子集解析（自写，零依赖）

覆盖**实测全部形态**，且在明确非字符串的形态上**主动诊断**而非静默出错：

| 形态 | 实测数量 | 处理 |
|---|---|---|
| 裸标量 `key: value` | 30 | 按**第一个 `:` 切**（值里的 `: ` 天然安全） |
| 单/双引号标量 | **26** | 去外层引号；**不做完整 YAML 转义** |
| `>` 折叠块 | **2** | 缩进续行用**单空格** join，末尾 trim |
| `>-` 折叠块 | **1** | 同 `>`（chomping 差异对单行化无意义） |
| 字面块（`\|` / `\|-`） | 0（**仍支持**） | 先保留换行，随后由单行化压平 |

- **统一规则**：任何 `key: value` 后紧跟的**缩进行**都算续行 —— 一条规则同时覆盖折叠块与
  plain-multiline，且天然终止于下一个非缩进的 key（实测 `lark-whiteboard` 的
  `description: >` 之后紧接**顶格**的 `metadata:`，正好命中）。
- **只认 5 个 key**（`name`/`description`/`disable-model-invocation`/`user-invocable`/`argument-hint`）；
  其余（`version` 28 个 / `metadata` 27 个 / `license`）整体忽略 —— 「有缩进即跳过」自然吃掉嵌套。
- **两个 invocation 字段独立解析（默认均 `true`，不得合并成一个 bool）**：
  `disable-model-invocation: true` ⇒ `model_visible = false`；`user-invocable: false` ⇒ `user_invocable = false`。
- **值的形态校验照 Claude Code**：取值以 `[` 或 `{` 开头（YAML 流集合）⇒ 判为**不是字符串**，
  warn + 丢弃该字段（不静默塞进提示词）。
- `description` 缺失/空 ⇒ **整个 skill 不加载**（一条规则同时吃掉 E2 与 pi 的 "description is required"）。
- `name` 缺失 ⇒ `label = command`。**不做 name 字符集校验**（CC 对个人/项目 skill 也不校验）。
- **块界** `^---\s*\n … \n---\s*\n?`（容 BOM/CRLF；无闭合 = 无 frontmatter）。**逐行状态机，不用正则。**

**已知不支持**（遇到即产诊断）：锚点/别名（`&`/`*`）、多文档、流集合。这是「守依赖基线」换来的代价。

### 3.5 压缩耦合修正（`fixed_prompt_tokens`）

**现状**（`crates/ys-loop/src/basic.rs:140`）：

```rust
let estimated = crate::token::estimate_session_tokens(messages);
if estimated > policy.trigger_at(window) { … }
```

**只算 session 消息**。修法是**加法式、最小**的：

```rust
if estimated + ctx.limits.fixed_prompt_tokens > policy.trigger_at(window) { … }
```

- `RunLimits` 增 `fixed_prompt_tokens: usize`，**默认 0 ⇒ 既有行为逐字节不变**；
- app 在 `main.rs` **启动期**用 `estimate_text_tokens(system_prompt) + estimate_text_tokens(&serde_json::to_string(&specs))`
  算一次；
- **刻意不改 `CompactPolicy::trigger_at`** —— 它的签名与语义（含 P1 不变量 `trigger > keep`）
  原样不动，扣减发生在**比较的输入端**。
- **R5 边界**：`fixed ≥ trigger_at(window)` 时**跳过压缩**（压缩已帮不上忙）并给一条启动期明确提示
  （「窗口装不下固定开销，请调大 `context_window` 或减少 skill」）。这是本修正的新边界，**必须补测试**。

### 3.6 TUI 通路

- `CodingView` 增 `skills: Vec<SkillEntry>` 与 `skills_omitted: usize`（纯数据，`ys-tui-coding` 不认识 app 类型）；
  后者是 R3 的可见性出口，由 `/status` 显示。
- `commands::parse(input, skills)`：**内置命令 > skill**（内置命令是 `Request` 穷尽 match 的契约，
  skill 是可增删的数据；若 skill 能遮蔽 `/status`，装一个 skill 就能让内置命令静默失效）。
  命中 skill ⇒ 发 `Request::Prompt("/<name> <args>")` **原文、零展开**。
  `user_invocable: false` 的 skill **不参与** `/` 解析。
- `help_text(skills)` / `command_help_text` 追加 skill 段；`/help <skill-name>` 可查单条。
- `completion::{entries,matches,open}` 收 `skills`：候选 = 内置表 + `user_invocable` 的 skill，
  **内置在前**（与优先级一致）。
- 补全浮层与 `/help` **同源于一处**，故「浮层里看得到、敲下去却不认识」在结构上不可能发生。

### 3.7 诊断与可观测性

| 时机 | 内容 | 去处 |
|---|---|---|
| 启动期 · 遮蔽 | 项目级覆盖用户级 —— 「`/git-status` 来自 `<project path>`，用户级同名被取代」 | 与 toolset 降级提示**同源**：TUI → `Outbound::Output`；`-p`/`--json` → stderr |
| 启动期 · frontmatter | `[`/`{` 开头判非字符串、不支持形态、`description` 缺失致跳过 | 同上 |
| 启动期 · 短路 | 命中自定义 `SYSTEM.md` ⇒ **不注入 skill 目录**，但发一行「`/skill-name` 仍可用」 | 同上 |
| 启动期 · R5 | `fixed ≥ trigger_at` | 同上 |
| 命令期间 | 无（`expand_invocation` 静默；正文进 transcript 即是回执） | — |

**`omitted` 计数**进 `/status`（走 `commands::status_text`）—— 超预算后模型看不到被收起的部分，
用户必须能看见。

## 4. 与设计的偏差（实现前实测，2026-09-21）

以下 5 处是 `design.md` 未写、但**实现时必须照做**的现实约束。均已在 `master`（`981a401`）核对。

| # | 现实 | 对计划的强制约束 |
|---|---|---|
| **D1** | `toolset::merge_hints` 是**私有**函数（`toolset.rs:118` `fn merge_hints`），且只接受**两个**来源（搜索 / web） | skill 诊断**不得**复用该函数、**不得**把它改成 pub。改为：`build_tools` 返回的 `hint: Option<String>` 与 skill 诊断在 `main` 里用 `"\n"` 拼接成一条字符串 —— 与 `merge_hints` 的三源出口**语义一致**（TUI → `Outbound::Output`，`-p`/`--json` → stderr），但**不触碰 `toolset.rs`**（见 D5）。 |
| **D2** | `prompt::find_custom_prompt` 是**私有**的（`prompt.rs:196` `fn find_custom_prompt`） | 自定义 prompt 短路时仍要发一行启动提示 ⇒ `prompt.rs` 新增 `pub fn has_custom_prompt(cwd: &Path) -> bool`（**薄包装**，复用 `find_custom_prompt`）。**不得**改为 pub 原函数（它返回 `Option<String>`，会把整份 prompt 泄漏给调用方）。 |
| **D3** | `main.rs` 里 `resolve_limits(&config)` 在 **678 行**，而 `build_system_prompt` 在 **717 行** —— limits **早于** system prompt 构造 | `fixed_prompt_tokens` 的赋值必须**后置**：`let limits = resolve_limits(&config)` 改成 `let mut limits = …`，在 717 行之后追加 `limits.fixed_prompt_tokens = estimate_text_tokens(&system_prompt) + estimate_text_tokens(&serde_json::to_string(&specs).unwrap_or_default());`。**不得**把 system prompt 的构造上移（`build_tools` 与 `sweep_fetched` 的顺序是承重的）。 |
| **D4** | `CodingView` **不是** `#[non_exhaustive]`（`view.rs:28-29`） | 加字段会打断**全部穷尽字面量**（实测 **9 处**，比设计记的 8 处多一处 `for_test`）：`crates/ys-tui-coding/src/view.rs:55,106,152`、`prompter.rs:204,217`、`draw.rs:883,925,950`、`apps/coding-agent/src/view.rs:71`。**全部必须显式补 `skills: Vec::new()` 与 `skills_omitted: …`**（不引 `..Default::default()` —— 那会让后续新增字段静默漏填）。 |
| **D5** | 选定路线**完全不碰** `toolset.rs` | `EXPECTED_ORDER`、`build_tools` 的 `vec!`、3 处 `assert_eq!(tools.len(), 9)`（`226/316/493`）、`prompt.rs` 的 `tool_snippet`/`tool_guidelines` 及其断言 **一律不动**。工具面仍是 **9 个**。任何本计划的任务若改到 `toolset.rs`，即为**设计偏离**。 |

## 5. 非目标

- ❌ **不建 `skill` 工具**（ADR-0019 决策 1）。
- ❌ **不加 `Request` 变体**（决策 2）。`Request` 仍是 7 个变体。
- ❌ **不引 YAML / regex / globset / walkdir**（守 ADR-0015/0016 依赖基线）。
- ❌ **不做** `SkillSource` trait / registry / aliases / `passthrough` / `SkillLoaded` 事件 / JSON `enum`。
- ❌ **不做** skill 的热插拔 / 市场 / 运行期增删 —— 列表是**启动期静态扫描**的数据。
- ❌ **不做** skill 的权限 / 沙箱（本项目「不做安全」）；`scripts/` 不自动执行（要走也得用既有 `bash` 工具）。
- ❌ **不做**正文的 Claude 专有工具名**符号映射** —— 只在目录前言加一句**能力边界声明**
  （「本 runtime 无 subagent / plan mode」），逐字断言，原样注入、失效自负。
- ❌ **不扫** `~/.claude/skills`、**不扫**父目录、**不开**路径配置项（守 D2/D2′）。

## 6. 测试

**单元（模块内 `#[cfg(test)]`）**

- **frontmatter 解析**：裸标量（值含 `: `）/ 单引号 / 双引号 / `>` 折叠 / `>-` / `|` 字面块 /
  BOM / CRLF / 无闭合 `---` / `[`、`{` 开头判非字符串 / `metadata:` 顶格终止续行。
- **`description` 缺失或空 ⇒ 整条不加载**（变异测试：删掉这条守卫 → 用例必须变红）。
- **`scan`**：目录不存在 / 空目录 / 无权限 ⇒ 静默零 skill + 零 panic（E1）；
  只扫一层，`references/` `scripts/` 不下探；非 UTF-8 的 `SKILL.md` 不 panic。
- **`catalogue` 冲突去重**：同名 `command` ⇒ **project > user、整条替换、被遮蔽者产一条诊断**；
  变异测试：改成字段级合并 / 改成 user > project → 用例必须变红。
- **`catalogue` 预算**：超 `Budget.total_bytes` ⇒ 按 name 升序收 + `omitted` 计数正确 +
  末尾 `- (N more skills omitted)`。
- **`expand_invocation`**：命中 / 不命中 / 带 args / `user_invocable: false` 不展开 /
  首 token 带 `/` 但非 skill ⇒ `None`。
- **系统提示严格前缀不变量**：`build_system_prompt(…, 空 catalogue)` 必须是
  `build_system_prompt(…, 非空 catalogue)` 的**严格前缀**（逐字节）。
- **`prompt.rs` 既有测试全绿**：`test_custom_prompt_takes_precedence` /
  `tool_list_is_derived_from_specs_order_verbatim` / `every_real_toolset_tool_has_non_fallback_snippet`
  **逐字锁死**，本计划不得改动它们的断言。
- **压缩触发**：`fixed_prompt_tokens = 0` ⇒ 既有全部压缩用例**逐字节不变**；
  `fixed > 0` ⇒ 触发点**提前**；`fixed ≥ trigger_at` ⇒ **跳过压缩**（R5）且不 panic。
- **TUI**：`parse` 中 skill 命中 ⇒ `Request::Prompt` 原文；**内置命令遮蔽 skill**（造一条
  `command = "status"` 的 skill，`/status` 仍走内置）；`/help` 列出 skill 段；
  补全候选 = 内置 + `user_invocable` skill、内置在前；`/status` 显示 `omitted`。

## 7. 风险 / 待定

- **R1（已验证 ✅）**：模型是否可靠地 `read` location —— 真实模型 + 真实 agent 实测 **5/5** 命中，
  12 skill 干扰零误读，且**照正文行事**。**但附带限定**：任务可被直接回答、描述匹配为**推断性**时
  模型可能**根本不加载**（1 次观测）⇒ 模型自主路线是**机会性**的，**`/skill-name` 的确定性路线是必备而非冗余**。
- **R2（必然发生，只能限定）**：项目级 skill 使前缀**随 cwd 抖动**（多 ~9.6k 的一次性 miss）。
  这不是本设计引入的（`<project_context>` 早已随 cwd 变）。纪律：**绝不为省缓存而阉掉项目级 skill**。
- **R3**：预算超限后模型看不到被收起的部分 —— 靠 `omitted` 进 `/status` + 文案给「如何列出全部」的线索缓解。
- **R4**：项目级覆盖用户级 = **静默换指令**。已用启动期诊断缓解，但**诊断只在启动期可见**，残余风险记档。
- **R5**：小窗口下 `fixed_prompt_tokens ≥ trigger_at(window)` ⇒ 压缩帮不上或永不触发。
  **实现时处理**（跳过压缩 + 明确提示），**必须补测试**。
- **R6**：压缩会把刚注入的 skill 正文摘要掉（E5）。**不引入「skill 正文免疫压缩」这种新机制**
  （会破坏压缩的单一阈值语义）；缓解 = 名字常驻系统提示，模型可重新 `read`。
- **R7**：正文里 ~20 个 Claude 专有工具名静默失效（`Agent` 占 16~17 个）。**不做符号映射**；
  只在目录前言加一句能力边界声明。
- **R8**：token 估算器未与真实 `Usage` 对账 —— 落地后**必须**校准一次（见 §6 集成测试）。
- **待定（实现时定）**：`Budget.total_bytes` 的具体默认值（口径 = 「≥ 当前 56 条语料 ⇒ 今天恒不触发」，
  **不据 CC 的 1%×128k 口径决策** —— 未核实且与该功能存在矛盾）；`/help` skill 段的具体版式。
