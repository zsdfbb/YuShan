# Follow-up（追问）设计计划

> 日期：2026-09-15
> 决策记录：ADR-0014（为什么有 follow-up，却没有 hook 系统）
> 性质：**新增能力的设计**。本文件只讲 follow-up；不含任何 hook 系统内容。

## 1. 背景与动机

**需求**：agent 在一个回合里执行 `git commit` 之后，希望**自动**再起一轮，让它检查并更新
`AGENTS.md`（及同类文档），保证文档与代码一致。

**为什么不能用提示词 / 工作流**：两者都依赖**模型自觉** —— 它可能忘记、可能判断错。
要做到「每次提交后必然发生」，触发必须是**代码**，不是提示。

**为什么不是 hook 系统**：见 ADR-0014。简言之 —— 手里只有一个真实消费者，
按项目自身的「**不设计假想未来需求**」，通用 hook 系统**有意推迟**。

## 2. 概念边界（必须先分清）

三级结构（前两级已存在，第三级为本计划新增）：

| 层级 | 定义 | 代码位置 |
|---|---|---|
| **轮**（Round） | 回合内一次「模型调用 +（可能的）工具执行」 | `BasicLoop` 的 `loop`（`basic.rs:89`） |
| **回合**（Turn） | 一次输入 → 一个最终回答 | `run_turn`（`basic.rs:44`） |
| **追问**（Follow-up） | 回合**结束后**、由系统发起的**下一个回合** | **新增**（`app_loop`） |

与相邻概念的区别 —— 判据是**「是否结束当前回合、另起一个新回合」**，**不是**"谁发起"：

| | 谁发起 | 位置 | 增回合数 |
|---|---|---|---|
| 轮内工具 | 模型 | 回合内 | 否 |
| 插话 `Steer` | 用户 | 回合内（轮边界） | 否 |
| 压缩 `Compaction` | 循环 | 回合内（轮边界） | 否 |
| **追问** | **系统** | **回合之间** | **是** |

> **两个易混点**（都记在 `CONTEXT.md`）：
> - **追问 ≠ 插话**：`Steer` 不增回合数（`basic.rs:140` 注释：轮内的额外输入，不是新一轮）。
> - **追问 ≠ 压缩**：压缩在**回合之内**、轮边界，且**已实现**（`basic.rs:130-137` → `compact_session`）；
>   `/compact` **命令**仍是占位（`capabilities.rs:194-200`，实为 `clear_session`）——那是**独立缺口**，与本计划无关。

## 3. 设计

### 3.1 形状：一个 seam，不是一套框架

`app_loop.rs` 的 `Request::Prompt` 分支，把「跑一个回合」包进一个可重复的循环：

```rust
Request::Prompt(message) => {
    let mut pending = Some(message);
    let mut follow_ups: u32 = 0;
    while let Some(msg) = pending.take() {
        turns += 1;
        let head_before = git_head(&workspace_root);   // 回合前记一次
        let outcome = { /* 现有 select! 回合逻辑，输入改用 msg */ };
        // ...（现有：排空事件信道、stats.record、失败落日志）...

        if let Some(next) = post_turn_follow_up(&workspace_root, head_before.as_deref(), follow_ups) {
            pending = Some(AgentInput::text(next));
            follow_ups += 1;
        }
    }
}
```

**关键约束：一个函数一个 seam。** 不引 `trait`、不引 registry、不引 `HashMap`。
将来若要「可插」（多点、多来源），再把这**一个函数**升级成列表 —— 那是加法，不是重写。
**今天不预埋任何抽象。**

### 3.2 检测：HEAD 前后对比

```rust
/// `git rev-parse HEAD`；非 git 仓库 / 无 git / 命令失败 → None
fn git_head(ws: &Path) -> Option<String>;
```

回合开始前记一次、结束后再记一次，**两者不等**即视为「这一回合里发生过提交」。

**为什么不解析命令参数**（在 tool args 里找 `git commit`）：**脆** —— `git ci`（别名）、
`a && git commit`、`bash -c "..."`、`git -c x=y commit` 都能绕过。

**为什么不装 `.git/hooks/post-commit`**：要往**用户仓库**里写文件，越界；且「谁读标记、何时读」
要额外设计。

**好处**：HEAD 对比**也覆盖用户自己**的提交，不只是 agent 的。

### 3.3 三样护栏（缺一不可）

1. **防套娃**：`follow_ups` 计数 + 上限（默认 **1**）。追问轮里若又提交，**不再**触发。
   ——没有这条就是无限套娃（同步文档 → 顺手提交 → 再同步 → …）。
2. **开关**：**默认关**。不是每个用户都想让 agent 每次提交都改文档。
   `Config` 增字段，来源可为 `YUSHAN_FOLLOW_UP_ON_COMMIT`（或后续 settings）。
3. **非 git 仓库静默跳过**：`git_head` 返回 `None` 时视为「检测不可用」，不追问、不报错。

### 3.4 改动面（**零依赖环**）

| 落点 | 改什么 |
|---|---|
| `apps/coding-agent/src/app_loop.rs` | `Prompt` 分支包循环；调用 `post_turn_follow_up` |
| **新增**小模块（如 `apps/coding-agent/src/follow_up.rs`） | `git_head` + `post_turn_follow_up`（纯函数，易测） |
| `apps/coding-agent/src/config.rs` | 开关字段 |

**不碰** `ys-loop` / `ys-runtime` / `ys-protocol`。这也正是把追问放在 `app_loop`（而非 `BasicLoop`）的理由：
「多回合驱动」本就归 `app_loop`（ADR-0010 附注），且 `RunResult` 住在 `ys-loop`，
hook 若从 `ys-component` 碰它会成**依赖环**（详见 ADR-0014）。

### 3.5 扩展轴（将来往哪长）

| 轴 | 今天（甲） | 将来 |
|---|---|---|
| **① 触发条件** | HEAD 变化 | 工具 X 跑了 / 文件出现 / 每 N 回 / 用户规则 |
| **② 判断来源** | 硬编码函数 | 从配置读 → 由插件提供 |
| **③ 追问内容** | 固定字符串 | 模板（带 diff / 路径）→ 插件生成 |

三条轴今天都**不实现**，但 seam 的形状（「回合结束 → 问一次 → 可选下一轮」）已为之留好。

## 4. 非目标

- **不建 hook 系统**（ADR-0014）。
- **不处理「回合后动作里不需要模型」的那类**（跑 linter、`git push`）—— 那只是「跑个命令」，
  不是追问；而 YuShan 不做 `app_loop` 内的任意 `exec`（工具都走循环）。**别为它设计。**
- **不碰 `/compact` 命令的占位问题** —— 独立缺口（那条是「真压缩」，不是「追问」）。

## 5. 测试

- **变异测试**（本项目约定）：删掉 `follow_ups` 守卫 → 「无限追问」测试**必须变红**。
- HEAD 变化 → 恰好追问 **1** 轮（且只 1 轮）。
- HEAD 不变（回合内没提交）→ **不**追问。
- 开关为关 → **不**追问。
- 非 git 仓库 → 静默跳过，回合正常收尾。
- 追问轮的 `Envelope.turn` **递增**（消费者可见）。

## 6. 风险 / 待定

- **UI 表现**：追问使 `turns += 1`，状态行回合数会**跳一格**。是否需要让 UI 区分「追回合」
  （如 `Envelope` 加标记）—— 待定。
- **追问输入的呈现**：那条自动生成的输入如何进 transcript？作为一条 `UserMessage` 显示，
  还是折叠/标注为「系统追问」？—— 待定。
- **检测的 `cwd` 口径**：`git_head` 用 `workspace_root` 还是 `cwd`？（两者当前通常相同）—— 实现时定。
