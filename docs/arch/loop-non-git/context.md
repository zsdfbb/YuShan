# loop-non-git — 架构上下文

> 日期：2026-02-24
> 状态：**探索中**（本文只记现状与约束，不含方案）
> 结论已定，见 [ADR-0073](../adr/0073-loop-time-driven-without-criterion.md)：**纯时间驱动，不加任何外部状态判据**。
> 本文保留探索过程与证据原貌，未澄清问题里已决的条目就地标注。
> 前序：`docs/arch/cross-turn-advance/`（唤醒 / 判据 / 动作三层划分的原始设计，已实现）

## 概述

`/loop <间隔> <提示词>` 是会话内的定时推进：到点醒来 → 过一次零 token 判据 → 有活才起回合。
当前判据只有一条 —— `git rev-parse HEAD` 是否与上次不同。后果：**非 git 工作区下
`/loop` 被直接拒绝、不登记**。本需求要让它在这类工作区下也能用。

## 现有架构

### 模块边界

| 层 | 落点 | 职责 |
|---|---|---|
| 命令解析 | `crates/ys-tui-coding/src/commands.rs:414` → `Request::Loop { interval_secs, prompt }`（`crates/ys-protocol/src/request.rs:108`） | 只解析间隔与提示词，不判工作区 |
| 登记 / 拒绝 | `apps/coding-agent/src/app_loop.rs:923-967`（`Request::Loop` 臂） | 取一次 `HEAD` 作基准；取不到 ⇒ 报一行诊断、**不登记** |
| 运行期状态 | `apps/coding-agent/src/app_loop.rs:334-350`（`LoopState`） | `next_at` / `interval` / `prompt` / `last_head`；`app_loop::run` 的局部变量，不进 `Wiring` |
| 唤醒 | `app_loop.rs:493-501`（`sleep_until(next_at)` → `Wake::TimerFired`）、`:628` 臂 | **只负责醒来**，不判断有没有活 |
| 判据 | `app_loop.rs:1860-1875`（`should_tick`）→ `apps/coding-agent/src/post_turn.rs:33-50`（`git_head`） | 零 token、不 append、快 |
| 动作 | `app_loop.rs:666-685`（`run_turn_chain` + `loop_placeholder`） | 真正起一个回合 |
| 基准更新 | `app_loop.rs:692-701` | 只在「`/loop` 创建」与「定时回合结束后」两处 |

**`ys-loop`（`BasicLoop`）与 git 无关**：crate 里没有任何 git 调用，定时策略完全在
`apps/coding-agent`。所以本需求的全部改动面在 app 层（外加 `post_turn.rs` 的纯函数）。

### 核心抽象

- `LoopState`（`app_loop.rs:334-350`）：单条语义（再敲 `/loop` 即覆盖）；`last_head` 是
  **判据基准**，注释明确它「只在创建时与回合结束后更新，零 token 的 tick 不更新」。
- `should_tick(workspace, last_head) -> bool`（`:1860`）：四条件 —— 有工作区、取得到 `HEAD`、
  `last_head` 为空（首次醒来）或与当前不同。
- `git_head(workspace: Option<&Path>) -> Option<String>`（`post_turn.rs:33`）：`None` 表示
  「非 git 仓库 / 无 git / 命令失败」三者不可区分。

### 关键数据流

```
/loop 5m 检查 CI
  └─ Request::Loop ──▶ app_loop 臂：git_head(cwd)
                          ├─ None ──▶ 报 "not a git repository" + 不登记
                          └─ Some ──▶ LoopState { next_at: now+5m, last_head }
                                          │
   每 5 分钟 sleep_until 到点 ──▶ Wake::TimerFired
     ├─ advance()（先推远，防忙转）
     ├─ should_tick(cwd, last_head) ── false ──▶ continue（零成本）
     └─ true ──▶ 刷「正在跑」视图 ──▶ run_turn_chain(loop_placeholder)
                   └─ 回合结束后 git_head() 重新取基准
```

### 外部依赖

| 依赖 | 用途 | 备注 |
|---|---|---|
| `git` 可执行文件 | `git_head` 取 `HEAD` | 子进程；显式 `env_remove("GIT_DIR"/"GIT_WORK_TREE")`，只认 `-C <cwd>` |
| `tokio::task::spawn_blocking` | 把阻塞的 git 调用挤出 app 循环 | 判据约束 C4 |
| `config.cwd` | 判据取点 | **不是** `worktree.get()`：共享工作区下后者是 `None` ⇒ 判据恒假 |

## 约束

- **技术**
  - 三层硬约束（`docs/arch/cross-turn-advance/design.md` §1）：唤醒 / 判据 / 动作**不可合并**，
    定时器绝不直接起回合。
  - 判据四条硬约束（同文档 §4.3）：C1 不调模型、C2 不 append 进 session、C3 命中后先 `advance()`、
    C4 毫秒级且不阻塞用户输入（跑在 `select!` 之后，同一线程）。
  - 依赖方向（`AGENTS.md` 硬性约束）：`ys-loop` / `ys-core` 不感知 app 层策略；git 只能留在
    app 层。
  - **工作区不受 git 管辖是合法形态**：纯脚本目录、临时目录、生成产物目录、非 git VCS 里的子目录
    都很常见；`config.cwd` 在运行期还会被 `/resume`、`-w`（worktree）改写（`main.rs:3232/3268/3330`、
    `app_loop.rs:1526/2637`）。
- **性能**：判据每间隔跑一次、在同一线程上。git 版成本 ≈ 一次 fork+exec（微秒级被测，实际毫秒）。
  任何替代判据必须给出**遍历上限**（文件数 / 字节 / 耗时）与超时退化行为。
- **演进**：设计已预留「只换判据」的位置（§4.2 的 `has_work` 接线口、§494 的「甲→乙是加法」）；
  二期/三期本来就要换判据（mtime → todo 清单），所以**多信号判据不是新增复杂度**。
- **组织**：无并发改动者；改动集中在 `apps/coding-agent/src/{app_loop,post_turn}.rs` + 对应用例。

## 为什么今天的判据是 git HEAD（原始依据）

这部分是问题的核心：**HEAD 不是为 `/loop` 选的，是为「提交后追加回合」（follow-up，一期）选的，
二期定时盯梢沿用了它。**

| # | 理由 | 出处 |
|---|---|---|
| 1 | 必须是**外部可观测事实**，不能由模型自述触发（ADR-0041） | `design.md:215-218`、`:526-530` |
| 2 | **零 token、零成本**：一次 `rev-parse`，可进判据 | `design.md:331` |
| 3 | **排除文件 mtime**：工作区里任何后台进程（编译器、编辑器自动保存）都能碰它 ⇒ 假阳性常态化 | `design.md:315-318`、`app_loop.rs:1852-1854` |
| 4 | **排除外部命令**（`gh pr checks` / `make -q`）：起进程秒级，同时破坏 C1 与 C4 | `design.md:318`、`:333-336` |
| 5 | **排除解析工具参数找 `git commit`**：别名、`&&`、`bash -c` 都能绕过，脆 | `design.md:122-124` |
| 6 | **排除 `post-commit` hook**：要往用户仓库写文件，越界 | `design.md:125-127` |
| 7 | **代价不对称**：假阴性（有活说没活）= 严重；假阳性 = 白跑一个回合，可接受 ⇒ 判据宁可宽松 | `design.md:349-357` |

⚠️ 关键事实：**没有任何一条理由说了「必须有 git」**。git 是「当前唯一已实现的廉价外部信号」，
不是必要条件。判据层本来就被设计成可替换的 —— 一期 header 里写明「二、三期只换唤醒源与判据，
动作层不动」（`design.md:37`）。

已知误差（同一来源）：
- 只看 `HEAD` ⇒ 漏掉「改了文件但没提交」的工作（`design.md:323-325`，号称由提示词让模型自查）。
- **空 git 仓库（`git init` 后无 commit）也会被拒**：`git rev-parse HEAD` 退出码 128
  （`fatal: ambiguous argument 'HEAD'`）；此时提示语「not a git repository」与实际原因不符。
- `.git` 仅存在于**子目录**（cwd 本身不在仓库内）同样被拒 —— `git -C cwd rev-parse` 走的是 cwd。

### 把 `HEAD` 判据放到「定时循环」这个位置上，它答不了的两件事

`HEAD` 判据的**原始服务对象是一期 follow-up**（提交后同步文档，工作定义就是「提交了」）。
二期把它原样搬给定时器时，语义发生了错位：

**① 「有活」被偷偷定义成了「git 能看见的文件变化」。** 定时循环的正当工作形态里，
大量情形**根本不改工作区**：

| 形态 | 例子 | `HEAD` 判据的结果 |
|---|---|---|
| 展示 / 汇报 | `/loop 10m 总结一下最近的测试失败` | 恒假 ⇒ 永不执行 |
| 调本地脚本、读它的输出 | `/loop 30m 跑一遍 lint 脚本看一下结果` | 脚本若不落盘 ⇒ 恒假 |
| 远程状态 | 查新 issue / PR 评论 / CI（`context.md:215` 的场景 2 本身就是这个） | 恒假 ⇒ 永不执行 |
| 纯维护 | 清理、归档（`research.md:53` 记录的默认提示词含「空闲时清理」） | 恒假 ⇒ 永不执行 |

⇒ 这是一类**语义性**错误，不是「非 git 目录」这个边角情形。设计里对它的处置是
「写进提示词让模型自己看」（`design.md:323-325`），但判据在模型看到提示词**之前**
就把回合砍掉了，模型拿不到这个自救机会。

**② 成本刹车被放在了一个答不好它的地方。** 判据实际背着两个目的（`design.md:297-336`）：
C2 不 append（防会话膨胀）、成本控制（用户猜错间隔后不至于无限跑）。用「内容没变就不跑」
同时答这两问，只在「定时 = 盯变化」这个假设下成立；对上面那四类工作它要么永不跑、
要么每轮都算「有活」。

而**真正的成本界至今不存在**：`LoopState`（`app_loop.rs:334-350`）只有
`next_at / interval / prompt / last_head`，没有 tick 计数、没有过期时长；`LoopView`
（`crates/ys-tui-coding/src/view.rs:161-170`）也只有 `interval` 与 `next_label`。
⇒ `HEAD` 判据成了**唯一**的刹车，于是被迫承担一个它答不好的职责。

**③ 而且这个刹车基本不被用到 —— 它防的情形本身几乎不存在。** “猜错间隔然后 AFK”
是假设出来的坏情形；`/loop 5m <提示词>` 本身就是用户显式下达的周期指令，用户敲它的
意图就是“每 5 分钟做一次这件事”。真正需要防的是“忘了关”，而那个由**次数/时长上限**
一句就答得干净（一次比较 u32），不需要任何外部信号。

### 结论：判据是过度设计

四问下来判据没有一个是站得住的：

| 它声称解决的问题 | 实际情况 |
|---|---|
| 省 token（没活不跑） | 误判为“没活” = 工作不发，而定时命令的**每个周期都是活** |
| 防会话膨胀（C2） | 一条短 harness 消息（标题 + 提示词 + 回合内容），同类消息本来就在大量追加；且压缩（Step 4b）已按阈值自动接管 |
| 防失控花费 | 次数/时长上限一句话就够，且不会误伤 |
| “盯变化”场景 | 这应该由用户写进提示词（模型自己看 git/CI），不由 harness 事前拦截 |

而它的**代价是实打实的**：一层额外的判据抽象、取不到信号的目录被拒登记、
四类合法工作全部落空、判据语种（HEAD vs 指纹）需持续维护。**加判断的成本大于它省的东西。**

## 需求范围

### 范围内

- 定时循环**默认定时即执行**：到点起回合，不以「外部状态变了」为前提。
- 非 git 工作区：不再拒绝登记。
- 成本由一个**硬上限**（次数或总时长）管：到达后自动停 + 一行说明，而不是由「内容变没变」管。
- 空 git 仓库、`.git` 只在子目录等「形式上是 git 但取不到 HEAD」的情形不再特殊对待。

> 本方向否定“加外部信号判据”本身（见上节结论）。若要保留“只在变化时跑”的用法，
> 它是**用户提示词里的一句话**（“若无变化就简述一句并停”），不是 harness 的机制。

### 范围外（明确不做的）

- **语义判断**（这活干完了没）：属三期，任何零 token 判据都做不到（`design.md:338-347`）。
- 落盘调度器 / 跨会话恢复 / 崩溃后续跑（`/loop` 至今不随 `--resume` 恢复，`research.md:235`）。
- 多循环并存（当前单条语义是有意的）。
- 非 git 之外的其他 VCS 适配（除非用户点名）。

### 关键场景

1. 非 git 目录 + 只读工作：`/loop 10m 汇报构建状态` ⇒ 每次到点都起回合（工作不落地也照样跑）。
2. 远程状态检查：`/loop 5m 看有没有新 issue` ⇒ 不依赖 `HEAD`。
3. 需要「只在变化时跑」的人：显式选变化判据档，非 git 目录下退化为总是执行（**不是**拒绝登记）。
4. 成本兜底：`/loop 5m` 无人值守跑满 N 次后自动停 + 一行说明；状态行能看到已跑次数。
5. `/loop off`、`/new`、`/resume` 对循环的现有语义不变。
