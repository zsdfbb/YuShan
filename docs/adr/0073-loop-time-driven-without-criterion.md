# ADR-0073：`/loop` 去掉外部状态判据，改为纯时间驱动

**状态**：accepted
**日期**：2026-02-24
**相关**：ADR-0041（撤掉完工复核回合 —— 它反对「模型自述」作触发依据，
本 ADR **不改**它）、ADR-0010 附注（多回合驱动归 `app_loop`）、
ADR-0014（不建 hook 系统）、ADR-0024（长程 todo 闭环）、ADR-0072（todo + 证据验收）
**本文替换**：`docs/arch/cross-turn-advance/design.md` §4.2–§4.5 中二期定时器的判据层
（`should_tick` / `LoopState.last_head` / `has_work`）。该文档保留原貌并加撤销标注；
一期 follow-up 的 `git HEAD` 判据**不受影响**。

## 上下文

`/loop <间隔> <提示词>` 是会话内的定时推进：到点醒来，先跑一个**零 token 判据**，
通过才起回合。当前判据只有一条 —— `git rev-parse HEAD` 是否与上次不同
（`apps/coding-agent/src/app_loop.rs` 的 `should_tick` → `post_turn::git_head`）。
取不到 `HEAD`（非 git 工作区、空仓库、`.git` 只在子目录）⇒ `Request::Loop` 直接拒绝登记。

**这个判据不是为定时器设计的。** 它来自一期 follow-up（提交后追加一个回合，工作定义就是
「提交了」⇒ `HEAD` 变了就是「有活」），二期定时器原样沿用了同一条纯函数，只换了基准
（一期比「本回合前后」，二期比「上次 tick 之后」）。

把 `HEAD` 判据放到「定时循环」这个位置上，语义发生了错位，而它承担的职责也超出了它的能力。
本 ADR 记录三个事实：

1. **判据答不了「有没有活」**，只答得了「git 能看见的文件变化」；
2. 它实际背着的成本刹车目的（防会话膨胀 C2、防失控花费）**至今没有任何真正的实现**
   —— `LoopState` 只有 `next_at / interval / prompt / last_head`，没有任何计数或时长上限；
3. 它防的那个坏情形（猜错间隔然后 AFK）本身几乎不存在 —— `/loop 5m <提示词>`
   就是用户显式下达的周期指令。

## 决策

**删除判据整层，定时器到点即起一个回合（纯时间驱动）。**

删除范围：

| 删除项 | 位置 | 现状 |
|---|---|---|
| `should_tick` 及其四条件 | `apps/coding-agent/src/app_loop.rs` | 「有工作区 / 取得到 `HEAD` / `last_head` 为空或与当前不同」⇒ 到点判一次 |
| `LoopState.last_head` | `apps/coding-agent/src/app_loop.rs`（`LoopState` 定义处） | 判据基准：`/loop` 创建时取一次、定时回合结束后再取一次 |
| `Request::Loop` 的非 git 拒绝分支 | `apps/coding-agent/src/app_loop.rs` 的 `Request::Loop` 臂 | `git_head(cwd)` 为 `None` ⇒ 报一行诊断、不登记 |

新语义：**到点就起回合**。`Wake::TimerFired` 仍先 `advance()`（把 `next_at` 推远，防忙转），
然后**不再**求值任何判据，直接走既有的 `loop_placeholder()` + `run_turn_chain`。

停止方式全部沿用既有路径，**本次不新增机制**：`/loop off`、`/new`、`/clear`、
`/resume` 换会话、退出进程。

**本次不新增次数/时长上限。** 上限是独立的后续可选增强（见「后果」与
`docs/arch/loop-non-git/context.md` 仍开放的 Q1/Q3/Q4），不作为本决策的补丁 ——
用「内容没变就不跑」去凑合它，正是本 ADR 要撤掉的那件事。

## 理由

### 1. 语义错位：「有活」被偷换成「git 能看见的文件变化」

定时循环的正当工作形态里，**大量情形根本不改工作区**：

| 形态 | 例子 | `HEAD` 判据的结果 |
|---|---|---|
| 展示 / 汇报 | `/loop 10m 总结一下最近的测试失败` | 恒假 ⇒ 永不执行 |
| 调本地脚本、读它的输出 | `/loop 30m 跑一遍 lint 脚本看一下结果` | 脚本不落盘 ⇒ 恒假 |
| 远程状态 | 查 CI / 新 issue / PR 评论 | 恒假 ⇒ 永不执行 |
| 纯维护 | 清理、归档 | 恒假 ⇒ 永不执行 |

这是**语义性**错误，不是「非 git 目录」这个边角情形：即使工作区是 git 仓库，
这四类工作在判据下也全部落空。远程状态的场景在设计文档里本就存在
（`docs/arch/cross-turn-advance/context.md:215` 的场景 2）。

### 2. 判据在模型看到提示词之前就砍掉了回合

设计文档对「只看 `HEAD` 会漏掉未提交改动」的缓解是**写进提示词让模型自己看**
（`docs/arch/cross-turn-advance/design.md:323-325`）。这个缓解**不成立**：
判据在提示词被渲染进请求之前就决定了「这一 tick 不跑」，模型没有任何机会自救。
凡把责任推给提示词的缓解，都要求那条路径先真的跑到模型面前。

### 3. 成本刹车放错了地方

判据实际背着两个目的：**防会话膨胀（C2：不 append 就不增长）** 与 **防失控花费**。
它用「内容没变就不跑」同时答这两问 —— 而这只在「定时 = 盯变化」的假设下成立：

- 对展示/汇报/远程状态/维护这四类，判据恒假 ⇒ 一秒 token 都省不下来，反而一行不跑；
- 对真正每轮都改工作区的活，判据恒真 ⇒ 一次都拦不住。

而**真正的成本界至今不存在**：`LoopState` 只有 `next_at / interval / prompt / last_head`，
`LoopView` 只有 `interval / next_label`（`crates/ys-tui-coding/src/view.rs:161-170`）。
因为它是唯一的刹车，就被迫承担一个它答不好的职责 —— 这是**职责错配**，
不是「判据还不够聪明」。

### 4. 它防的坏情形本身几乎不存在

`/loop 5m <提示词>` 就是用户**显式**下达的周期指令：用户敲下它的意图就是
「每 5 分钟做一次这件事」。把「猜错间隔然后 AFK」当成主要威胁，是从
「定时 = 盯变化」这个错误前提推出来的假想场景。

真正需要防的是「忘了关」—— 那由次数/时长上限一句就答得干净（一次 `u32` 比较），
不需要任何外部信号，也不会误伤任何一类工作。

### 5. 代价是实打实的

| 代价 | 具体表现 |
|---|---|
| 多一层抽象 | 判据函数 + 基准字段 + 「基准取自回合之后」这类实现期约定（`design.md` §8.1 前两行） |
| 取不到信号的目录被拒登记 | 非 git 工作区、空仓库、`.git` 只在子目录 —— 三种情形都报「not a git repository」，与实际原因不符 |
| 四类合法工作全部落空 | 见理由 1 |
| 判据语种需要持续维护 | HEAD / 文件指纹 / 多信号的分层与遍历预算，都是要长期维护的判据本体的复杂度 |

**加判断的成本大于它省的东西。**

## 后果

**正面**

- 非 git 工作区可用：不再拒绝登记，「有没有 git」与「能不能定时」彻底解耦。
- 四类正当工作不再落空：展示/汇报、读脚本输出、远程状态、纯维护到点即跑。
- 少一层抽象：`should_tick`、`last_head`、拒绝分支、以及围绕它们的那批用例一起消失，
  代码净减少；`post_turn::git_head` 回归一期的唯一消费者。
- 语义与用户输入一致：用户说「每 5 分钟做一次」就每 5 分钟做一次，不需要先让 harness
  猜「这活会不会改文件」。

**负面**

- 不再有「没变化就不跑」的能力。想只在变化时跑的用户，把这个条件写进**提示词**
  （「若无变化就一句话说明并停」），由模型自己看 git / CI —— 而不是 harness 事前拦截。
- 停靠用户 `/loop off`（以及 `/new` / `/clear` / `/resume` 换会话 / 退出进程）。
  这是刻意的：定时唤醒会在用户不看屏幕时花钱，停它的动作必须是明确的。
- **若用户给了很短的间隔，input token 开销会实打实发生** —— 每次 tick 至少是
  「系统提示 + 工具表 + 会话历史」的输入成本。这是**用户责任**：间隔由用户显式给出，
  harness 不再用「内容没变」替他打折。间隔下限（当前解析层校验）与次数/时长上限
  是后续可选的独立增强，不在本 ADR 内。

## 未采纳的替代方案

三条都试过，共同问题一致：**仍要把「工作形态」塞进一个 harness 猜不到的判据里。**

| 方案 | 具体形态 | 为什么不采纳 |
|---|---|---|
| ① 多信号：git 优先 + 文件指纹兜底 | `HEAD` 取不到或没变时，再比对工作区文件指纹 | 只是把「猜不到」推迟一层：仍然恒假于不改工作区的四类工作，同时新增遍历预算、忽略规则（`target/`、`node_modules/`）、超时退化方向三处需要长期维护的判据本体复杂度 |
| ② 统一文件指纹（不分 git / 非 git） | 一律遍历工作区算指纹 | 同 ①，且把假阳性来源扩大：任何后台进程（编译器、编辑器自动保存）都会碰 mtime ⇒ 判据退化为恒真，等于回到「到点就跑」但多付一次遍历 |
| ③ 把判据做成可选开关 | `/loop --on-change` 之类，默认关闭 | 两层语义并存：默认关死的那条路径缺少真实使用 ⇒ 无法被测试覆盖（现有测试已证明这类「登记成功但永不触发」的路径会静默误导用户）。而且它把「该用哪种」的判断题又推回给用户 |

**判据层的根本问题不是「信号选得不够好」，是它回答的问题本身问错了**：
harness 拿不到「用户想让这件事在什么时候发生」—— 那已经写在 `/loop` 的命令行里了。
唯一答得干净的成本控制是**次数/时长上限**，它与「有没有活」正交，不需要外部信号。

## 与既有决策的关系

- **不改 ADR-0041**。它否决的是「执行回合的模型自述」作为触发/放行依据 ——
  本 ADR 撤的是 harness 自己的外部信号判据，方向相反（少一层 harness 猜测），
  两者不冲突。
- **不改一期 follow-up**（`docs/arch/cross-turn-advance/design.md` §3）：
  「提交后追加一个回合」的工作定义就是「提交了」，`git HEAD` 在那里是**语义正确**的判据，
  继续保留。
- **不改三期**（todo 清单 + 证据验收，ADR-0024 / ADR-0072）：那里判的是「声称做完的项
  真做完了吗」，与本 ADR 的「这一 tick 该不该跑」是不同问题。
  三期判官与定时器的关系（ADR-0072 D12：目标激活期间抑制 tick）不变。
- **`design.md` §1「三层划分」的措辞需要在此处补一句适用边界**：唤醒与判据不可合并
  是结构约束；但「判据」这一层对定时器**可以不存在**（唤醒即动作），
  只要唤醒源本身没有额外语义。一期与三期仍各有自己的判据。
