## 全程纪律

- **每个单元的验收是 `./scripts/cargo-build.sh check --all-targets` 全量绿**，不是「本包能编就行」。
  本需求横跨 `adapters/tools-basic` 与 `apps/coding-agent`，单包绿而全量红是常态失败
  （典型：`tool_snippet` 缺 arm、`EXPECTED_ORDER` 与 `vec!` 顺序不一致）。
- **测试用 `./scripts/par-test.sh`**（跨二进制并行，≈7.4s）；需要 cargo 原生输出（`--ignored` e2e）时
  才单独跑 `cargo test`。直接跑 `cargo test --workspace` **不算跑过测试**。
- `./scripts/cargo-build.sh` 的清理阈值只在**改 `ys-core` 类底层 crate** 后才需要留意；本需求不碰
  `ys-core` / `ys-tool`，`target/debug/deps` 增长主要来自 `ys-tools-basic` 与 `ys-coding-agent`，
  正常时长跑不会撞阈值（默认 400,000）。若出现单次增量编译明显变慢，先看阈值再看代码。
- 每个 `impl` 单元的 review 用 `deep`，`test` 单元用 `shallow`（除 T4 —— 流水线含空结果三分与
  字节边界，用 `deep`）。
- 注释纪律：新代码注释只写**当前行为契约**；「为什么这么设计」指回 `docs/arch/ocr-tool/design.md` 的节号。

- **type**：`impl`
- **目标**：把 design §1 的 3 字段 schema 与 §关键数据流 的 ①②③④⑤ 五步落成一个 `Tool` 实现，

  - `spec()`：3 字段（`path` 必填 / `lang` 默认 `chi_sim+eng` 且描述写明「Vision 下被忽略」/
    `word_boxes` 默认 `false` 且描述写明「Vision 下退化为行框」）。`--psm` / `--oem` / `dpi` **不暴露**。

    存在/是文件/≤20 MB → header 读出的 `w*h` ≤ 40 MP（只读头，不解码）。失败一律 `InvalidInput`（早失败）。
  - **不实现 `Tool::timeout()`**，并写一句注释指回 design §3.1（防止后人「顺手加严」）。

    与 `bash_bg` 的 spawn 有副作用不同）。
  - 空结果三分（**不可合并**）：`lines==0 && filtered==0` ⇒ `NoTextDetected`（`is_error=false`）；
    `lines==0 && filtered>0` ⇒ `NoTextDetected` + 「N 行因宽度<6 被滤，可用 `word_boxes=true` 复取」；
    stderr 含 `Failed loading language` ⇒ **成功结果** + `degraded=lang-missing` + 一行安装提示。
    语言包缺失**不缓存到进程状态**（每次调用重复同一句 notice 就是正确语义）。

    `word_boxes=true` **恒落盘**。落盘路径必附「临时文件，可能已被系统清理；需要保留请先 `read` 或 `cp`」。
  - 失败分层照 design §3.3：候选全失败 ⇒ `Execution` 且**拼接每个候选的失败原因**；内层 deadline
    到点 ⇒ `Timeout`，文案区分「编译超时」与「OCR 超时」。

## 串行理由

- **W2 必须在 W1 之后**：`engine.rs` 的对外 API 就是 `mod.rs` 的**输入** —— 候选链怎么给、
  `spill` 返回什么（路径 / 字节数 / 是否全量）、`Kind` 有哪些变体，全部由 U3 定型。反过来做会让
  `mod.rs` 先按想象中的 API 写一遍，再由 U3 适配，等于把同一份契约写两遍（两份真值）。
  另外 `mod.rs` 在 W1 里已经要加一行 `pub mod engine;`，两个单元改同一文件 ⇒ 天然不能并行。
- **W3 必须在 W2 之后**：`toolset.rs` 要注册的是 `OcrTool`，它在 U4 结束前不存在；提前注册会让
  `apps/coding-agent` 在整个 W2 期间编译不过，违反「每单元 `check --all-targets` 全量绿」。
- **W4 必须在 W3 之后**：`design-final` 写的是「实现的**实际**形态」与「哪条变异测试真的会红」，
  只有 T5 绿了才有这两个事实可写。
