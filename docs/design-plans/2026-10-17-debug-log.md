# `--debug` 结构化执行日志（P0）设计计划

## 背景

- 需求原话：「先提高 agent 执行过程的可观测性，每次执行在启动 debug 选项时要输出充分的
  日志信息，提供给问题定位、性能分析等。」
- 权威设计：[`docs/arch/agent-observability/design.md`](../arch/agent-observability/design.md)
  + [`adr-debug-log.md`](../arch/agent-observability/adr-debug-log.md)；现状与约束见
  [`context.md`](../arch/agent-observability/context.md)；评审与处置见
  [`review.md`](../arch/agent-observability/review.md)（R1–R7 已全部处置）。
- 直接动因是三处实测盲区：33 轮里 3 个离群轮吃掉 36% 墙钟；一轮里单个 `bash` 吃掉 73.7 秒
  （逐调用计时已定位）；同一提示 `gen` 46 s vs 143 s **无法归因**（思考与正文混在一起）。
- 本轮目标：落 **P0** —— 开关、独立 JSONL、异步单写者、段的富计时、工具元数据、
  `run_start` / `run_end`、逐轮 usage（含 `reasoning_tokens` 与压缩覆盖）、14 处退出收敛。
  P1（`model_attempt` / 适配器自检）与 P2（轮转 / sweep / `state_change`）不在本轮。

## 设计

**不重述** —— 见 [`design.md`](../arch/agent-observability/design.md) 全文。P0 的七块：

| 块 | 内容 |
|---|---|
| 1 | `ys-core::Usage` 增 `reasoning_tokens`（`#[serde(default, skip_serializing_if = "Option::is_none")]`、纳入 `Add`） |
| 2 | `ys-event` 新增非终局 `AgentEvent::RoundUsage { purpose, round, usage }` + `RoundPurpose` |
| 3 | `ys-loop` Step 7 emit `purpose=Turn`；压缩分支 emit `purpose=Compaction`；`CompactOutcome` 带 `usage` |
| 4 | `ys-model-openai-compat` 解析 `completion_tokens_details.reasoning_tokens` |
| 5 | `apps/coding-agent/src/debug_log.rs`：开关、记录信封、**异步单写者 + 有界队列 + 丢弃计数**、参数摘要与脱敏 |
| 6 | `apps/coding-agent/src/round_clock.rs`：thinking/text 分段、计数、工具元数据、翻成 debug 记录；**既有文本行逐字节不变** |
| 7 | `main.rs` / `app_loop.rs`：`--debug` 解析、sink 创建、两条入口接线、`/new` `/resume` 切文件、**14 处 `process::exit` 收敛到 `exit_with_debug`** |

**必须遵守的裁定**（逐条来自 `design.md`，实现时不得弱化）：

- **只记段，不记增量**：`ModelTextDelta` / `ModelThinkingDelta` 零记录，只计数。
- **时间戳先取**：`RoundClock::observe` 入口的 `now` 是唯一时间源；摘要、序列化、入队全部在其后。
- **异步单写者**：调用线程只序列化 + `try_send`；队列满**丢当前记录并计数**，绝不阻塞；
  **一行一次 `write`**（进程被杀不留半行 JSON）。
- **关闭 debug 时零字节、零线程、零分配**：`Option<DebugSink>` 为 `None`。
- **`RoundUsage` 非终局**：终局事件仍只有 `RunFinished` / `RunFailed`；`--json` 是**加法契约**。
- **`dropped > 0` 的推断纪律**：不能据「某条记录不存在」作否定推断（"这轮没有工具调用"
  ≠ "工具调用记录被丢了"）。
- **脱敏无关闭开关**：`full` 档也必须脱敏；`write`/`edit` 正文零字节，webfetch query 一律 `<redacted>`。
- **不引新依赖**：JSONL 用既有 `serde_json`。

### 与设计文档的一处精确化

`Usage.reasoning_tokens` 用 **`Option<u32>`** 而不是裸 `u32`：

- `None` = provider **未上报**；`Some(0)` = 真 0。这正好实现 `design.md` §4.2 的
  `reasoning_tokens_reported` 与 §7 风险 3 的「不报时为 `null` 而非 0」。
- `skip_serializing_if = "Option::is_none"` 保证 `None` 时**不写这个键** ⇒ 关闭 debug 的
  `--json` 里 `RunFinished.usage` 行逐字节不变（T2 的前提）。
- `Add` 以 `None` 为单位元：`None + Some(x) = Some(x)`，`Some(a) + Some(b) = Some(a + b)`。
  这样回合累计不会把「某一轮没上报」伪造成 0。

## 测试策略

### 测试合同（Phase 3 审查依据）

> 每条需求一条验收条款。Phase 3 review subagent 按本节逐条跑命令 / 核对输出。
> 下表的 `T1`–`T9` 是**验收项编号**，与执行计划里的 `Task N` 不是同一套编号。

#### T1: 关闭 debug（负向验收）
- **验收方法**: 临时 `YUSHAN_LOG_DIR` + 固定内容的 `yushan.log`；以关闭 debug 的配置跑一次
  单元/集成路径。断言目标目录**零个** `debug-*.jsonl`、`yushan.log` **逐字节不变**。
- **优先级**: 必测
- **验收人**: review subagent

#### T2: 关闭 debug 的 `--json`（加法契约）
- **验收方法**: 用同一 stub provider 各跑一次改动前 / 改动后的二进制（`--json`，不带 `--debug`）。
  用 `jq` 过滤掉 `RoundUsage` 行后 `diff` 为空；未过滤时**恰好**多出每模型轮一条
  `RoundUsage`。另断言：`RunFinished.usage` 里 `reasoning_tokens` 为 `None` 时**不出现该键**。
- **优先级**: 必测
- **验收人**: review subagent

#### T3: 打开 debug + 10k 增量
- **验收方法**: 用合成事件流喂 `RoundClock` 10,000 条 `ModelTextDelta` /
  `ModelThinkingDelta`。断言 debug 文件 **< 200 KiB**；**零**增量记录；
  每行是合法 JSON；`seq` 严格 +1；`t_ms - dt_ms` 恒定（`t_ms` 由
  `run_start_unix_ms + dt_ms` 派生，整数运算保证严格恒定）。
- **优先级**: 必测
- **验收人**: review subagent

#### T4: 队列满
- **验收方法**: 注入慢 writer（测试专用构造，见执行计划 Task 10），入队量 > 队列容量。
  断言 `dropped > 0`；已写出的每一行都是完整合法 JSON；`flush` 后文件以 `\n` 结尾。
- **优先级**: 必测
- **验收人**: review subagent

#### T5: 不 flush 直接退出
- **验收方法**: **P1 推迟**（本仓没有可控的 `process::exit` 注入点；P0 已用 T6 的 grep
  钉住唯一出口）。P0 只验证 `flush` 写出的最后一行完整成行；「进程被 kill -9」留给 P1
  用独立子进程 + 超时杀进程验证。
- **优先级**: P1（在 P0 验收报告中注明）
- **验收人**: review subagent

#### T6: 退出路径收敛
- **验收方法**: `grep -c 'process::exit' apps/coding-agent/src/main.rs` 期望为 **1**，
  且该处在 `fn exit_with_debug` 内。另加一条单测：`include_str!("main.rs")` 计数并断言
  唯一出现位置（防止未来新增散落退出）。
- **优先级**: 必测
- **验收人**: review subagent

#### T7: 压缩覆盖
- **验收方法**: `cargo test -p ys-loop` 里跑一次强制压缩的回合，收集事件流；断言
  `RoundUsage` 同时出现 `purpose=turn` 与 `purpose=compaction`，且后者 `usage` 等于
  摘要调用的 `ModelResponse.usage`。
- **优先级**: 必测
- **验收人**: review subagent

#### T8: 五条变异
| 变异 | 应变红的用例 |
|---|---|
| 在 `RoundClock` 里给 `ModelTextDelta` 加一条记录 | T3（零增量记录） |
| 把摘要/序列化挪到时间戳**之前** | T3 的 `t_ms - dt_ms` 恒定 + `hot_path_ms` 上界 |
| 队列满改成 `send().await` | T4（慢 writer 注入会挂住） |
| `exit_with_debug` 改回裸 `process::exit` | T6 |
| 脱敏匹配删掉 | 脱敏断言（`[REDACTED]` + `args_redacted_keys`） |

- **验收方法**: 逐条注入后跑对应 `cargo test -p ...`，期望变红；恢复现场后全绿。
- **优先级**: 必测
- **验收人**: review subagent

#### T9: 真实 provider 验「思考 vs 正文」
- **验收方法**: 需 `YUSHAN_API_BASE` + `YUSHAN_API_KEY`，跑
  `cargo run -p ys-coding-agent -- --json --debug -p "<任务>"`；用
  `round_end.thinking_span_ms` / `text_span_ms` 与
  `round_usage.gen_ai.usage.reasoning.output_tokens` 交叉验证，回答
  「`gen` 里思考占多少」。**当前环境无凭证 ⇒ 人工确认**。
- **优先级**: MANUAL_ACK_REQUIRED
- **验收人**: 用户

## 风险与注意事项

- **`Usage` 加字段牵动 34 处 `Usage {` 字面量**（已核实）。带 `..Default::default()` 的自动兼容，
  其余按编译错误逐一补 `reasoning_tokens: None`；这是一次性机械修补。
- **`--json` 是加法契约**：新增 `RoundUsage` 事件；消费者必须忽略未知变体
  （`AgentEvent` 已 `#[non_exhaustive]`）。T2 用「过滤后比对」验收，不得写成「逐字节完全相同」。
- **关闭 debug 必须零开销**：`Option<DebugSink>` 为 `None`，热路径只剩一个可预测空判断；
  不得在 `round_clock` 里无条件构造 JSON。
- **测试隔离**：临时目录名含进程内原子序号 + `process::id()`；进程级 env 改写必须走
  `crate::test_env::env_lock()` + `EnvRestore`（见 CLAUDE.md「测试隔离」）。
- **UTF-8 边界**：参数摘要按**字节**截断时必须在字符边界收口；不得产生半个字符。
- **TUI alt-screen**：debug 只能落文件，不得写 stdout/stderr；`-p` 的 stdout 必须保持干净。
- **退出路径**：`process::exit` 不跑析构；任何新增退出都必须走 `exit_with_debug`，
  否则队列尾部会丢。
- **依赖方向**：`ys-core` / `ys-event` / `ys-protocol` 零 tokio、零 IO；计时与序列化只在 app 层。
