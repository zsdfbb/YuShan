# 0049 — 收场前拉一次轮边界：让「轮边界总是存在」成为不变量

修掉「模型正要收尾时到达的用户插话**静默消失**」这个丢消息故障，
并把 ADR-0047 决策 1 依赖的「轮边界总是存在」从**假前提**修成**真不变量**。

## Status

accepted（2026-10-22；依据 `docs/arch/input-delivery-latency/review.md` 的 F2 与 G2）

## 背景

### 故障形态

用户在**模型正要收尾**时插一句话 —— 那句话**既不生效，下一回合也不会带上**，静默消失。

实测（修复前的探针用例，`apps/coding-agent/src/app_loop.rs`）：

```
[PROBE] 本回合模型调用次数 = 1
[PROBE] steer 是否进入本回合最后一次请求 = false
[PROBE] steer 是否出现在后续任一请求 = false   ← 彻底丢失
```

对照组 `steer_is_injected_at_round_boundary`（多轮场景）**通过**
⇒ 插话通路本身是通的，问题只出在「模型给出最终答复」这一条路上。

### 根因

`BasicLoop` 拉边界消息的地方**只有一个** —— 每轮**开头**、组装 `ModelRequest` 之前。
而模型给出**最终答复**那条路（`tool_calls.is_empty()`）**直接 `return`**，
**不会再走一次轮边界拉取** ⇒ 这一轮**没有轮边界可取**。

更致命的是：插话已经被回合内的 `select!` pump 进了**本回合局部的**
`Arc<QueueBoundarySource>` ⇒ 回合结束即随作用域销毁。
app 侧那层兜底（`carry_over`）排的是 `boundary_rx`（UI→app 信道），
**盖不到已 pump 进边界源的消息** ⇒ 净丢失。

### 为何这是个假前提

ADR-0047 决策 1 的论证是：

> 「『当前这一轮』的下界由**轮边界**决定，与模型这轮还调不调工具无关
> （**轮边界总是存在**）。」

**「轮边界总是存在」在源码下为假** —— 模型收尾时不经过轮边界。
这恰是用户最需要插话的时刻 ⇒ ADR 承诺的「下一轮生效」在最常见场景下不成立。

## 决策

### 决策 1：收场前补一次轮边界拉取

把轮边界拉取抽成可复用函数 `drain_boundary(ctx)`
（`crates/ys-loop/src/basic.rs`），在**两处**调用：

| 调用点 | 时机 | 原有 |
|---|---|---|
| 每轮**开头** | 组装 `ModelRequest` 之前 | 已有（内联代码）⇒ 改为调函数 |
| **收场前** | 模型给出最终答复 / 截断答复、即将 `return` 之前 | **新增** |

收场前的处理与轮边界一致：

- 取到 `Steer` / `Deferred` ⇒ **append 进会话 + 发事件**，然后 `continue`
  ⇒ **继续本轮循环** ⇒ 模型下一轮就能看到它（用户不必等整个回合结束）；
- 取到 `Abort` ⇒ 以 `Cancelled` 收场（不伪装成 `Completed`）。

⇒ **「轮边界总是存在」成为真不变量**：任何时刻到达的插话，都有一个轮边界接住它。

### 决策 2：`Abort` 在收场前同样要生效

收场前那次拉取若取到 `Abort`，必须以 `Cancelled` 收场。
否则「用户在模型收尾时按 Esc」会被忽略 —— 与「插话不丢」是同一个洞的两面。

### 决策 3：**不**改 `Boundary` 枚举、**不**加协议变体、**不**动 app 侧

本修复是 `ys-loop` 内部的**时机**修补，不碰协议面：

- `Boundary` 仍是 `Steer` / `Deferred` / `Abort` 三格；
- `AgentEvent` 不加变体（`Steer` 走既有的 `UserMessage`，`Deferred` 走既有的 `DeferredResult`）；
- app 侧（`app_loop`）**一行不改** —— 它本来就把插话 pump 进边界源，
  缺的只是有人去取。

### 决策 4：抽成 `drain_boundary` 而非复制代码

两处拉取的处理逻辑（`Steer` append + emit、`Deferred` append + emit、`Abort` 收场）
**逐字相同** ⇒ 复制会让两条路径漂移（未来改一条忘一条）。
抽成一个函数，返回 `BoundaryDrain { Empty, Consumed, Aborted }`
—— `Consumed` 与 `Empty` 分开，是因为「取到了插话」要触发 `continue`，
而「什么都没取到」要正常收场。

## 不做什么

- **不改 `Boundary` 枚举**（决策 3）。
- **不新增 `AgentEvent` 变体**（决策 3）。
- **不改 app 侧接线**（决策 3）。
- **不做「降级到下一回合」的队列** —— 那是 ADR-0047 的其余部分（app 侧 `Delivery` 队列），
  **尚未实现**，与本修复正交：本修复保证「插话在本回合内不丢」，
  ADR-0047 解决的是「回合彻底结束后，系统发起的 follow-up 何时执行」。
- **不实现 `Delivery` / `DeliveryTarget` 协议** —— 同上，属 ADR-0047 未竟部分。

## Considered Options

### 选项 A：只在 app 侧把残留捞回来（不改 `ys-loop`）

回合末把本回合边界源里没取走的 `Steer` 取回，转成下一回合的输入。

- **优点**：不动 `ys-loop`（`BasicLoop` 行为零变化）。
- **缺点**：① 语义退化 —— 用户要的是「**下一轮**生效」，捞回来变成「下一回合生效」，
  而下一回合要等用户再提交一次东西才开始 ⇒ 用户仍要等；
  ② 需要把边界源的 `Arc` 提到回合之外（app 侧结构改动）；
  ③ 「绝不丢失」仍要靠 app 侧队列兜底 ⇒ 引入 ADR-0047 的全套复杂度。
- **不采纳**：它治的是**症状**（丢消息），不是**病根**（收场路径没有边界）。

### 选项 B：补最终答复前的拉取点（**采纳**）

见决策 1。

- **优点**：① 语义正确 —— 插话**下一轮**即可见，与 ADR-0047 决策 1 一致；
  ② 改动局部（`ys-loop` 一个文件 + 两个新用例）；③ 零协议破坏；
  ④ 顺带把 ADR-0047 的假前提修成真不变量。
- **缺点**：`BasicLoop` 的收场路径多了一次拉取（可忽略的开销）。

### 选项 C：承认现实，把承诺降级为「下一轮**或**下一回合」

评审 F2 给的「A 路」：不修 bug，改文档措辞。

- **优点**：零代码改动。
- **缺点**：**消息仍然丢**。用户在模型收尾时插的话静默消失 ——
  用户看到输入框里的文字没了，没有任何提示。**丢消息比晚点生效严重得多**
  （与 ADR-0047 选项 A 被否决的理由同源）。
- **不采纳**：掩盖故障而非修复故障。

## 风险与规避

| 风险 | 规避 |
|---|---|
| 收场前多拉一次边界 ⇒ 「本该收场」的回合多跑一轮 | 只有**真的取到插话/后台结果**才 `continue`；没有就正常收场（`rounds` 不变） |
| 收场前的 `Abort` 把正常收场变成 `Cancelled` | 这是**正确**行为（决策 2）；用户按了 Esc 就是要中止 |
| `Deferred`（后台子 agent 结果）在收场前到达 | 与 `Steer` 同路径处理 ⇒ 结果不被丢弃，本轮多跑一轮把它交给模型 |
| 无限循环（插话持续到达 ⇒ 一直 `continue`） | 受 `RunLimits::max_rounds` 约束（Step 4 在轮首检查）；app 默认 `max_rounds = u32::MAX` 是个已知的弱阀，但**既有轮边界路径同样如此**，本修复不改变这个性质 |
| 既有测试依赖「模型给最终答复即收场」 | 全量测试通过（见下）；`rounds` 语义未变（只在取到插话时才 +1） |

## 测试矩阵

| 用例 | 位置 | 断言 | 变异 |
|---|---|---|---|
| 收场前到达的插话不丢 | `crates/ys-loop/src/basic.rs` | 插话进了会话；`rounds == 2`；发出 `UserMessage` | 跳过收场前的 `drain_boundary` ⇒ 变红（实测） |
| 收场前到达的 `Abort` 取消回合 | 同上 | `stop_reason == Cancelled` | 把 `Aborted` 当 `Empty` ⇒ 变红 |
| 端到端：插话被模型看到 | `apps/coding-agent/src/app_loop.rs` | 插话出现在某次模型请求里 | 同上 ⇒ 变红（实测） |
| 既有路径逐字节不变 | 全仓 | `cargo test --workspace` 全绿 | — |

**变异测试已实测**：两处（`ys-loop` 与 app 层）各自注入「跳过收场前的拉取」，
对应用例**均变红**（已实测，非推断）。
