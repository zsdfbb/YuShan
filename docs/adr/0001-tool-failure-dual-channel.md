# 0001 — 工具失败走双通道：错误结果是数据，ToolError 才终止回合

BasicLoop 遇到工具失败时区分两类失败：模型可理解的失败（命令退出码非零、目标文件不存在、请求了未注册的工具名）一律作为带错误标记的 ToolResult 回喂模型，让模型自愈或换路；只有 ToolError——工具无法产出任何可回喂结果的运行时失败——才以 LoopError 终止回合。

理由：agent 的核心价值之一是失败自愈；把「命令失败」当错误会让模型失去纠错机会。同时保留一条真正的错误通道，避免基础设施 bug 被模型无限重试放大。

## Considered Options

- 全部终止：行为最可预测，但模型无法从正常失败中恢复，agent 失去自愈能力。
- 全部回喂（ToolError 也转成错误结果）：Loop 最简单，但基础设施缺陷会变成模型与坏工具之间的死循环。

## Consequences

- ToolResult 需要错误标记；错误回喂计入轮数，由最大轮数兜底。
- Registry miss 也走错误结果通道（内容含请求的工具名），而非 LoopError。
